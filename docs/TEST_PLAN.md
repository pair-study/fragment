# 검증 계획 — 일감 (근무 플랫폼)

> PRD에서 분리된 기술 검증 문서. 단위 테스트, 통합/E2E 테스트, 수동 확인 시나리오, 기술 구현 리스크를 다룬다.

---

## 1. 검증 계획

### 단위 테스트 (Jest / Vitest)

- **급여 계산 엔진**
  - 주휴수당 — 주 14.9h vs 15h 경계, 결근 시 제외
  - 야간수당 — 22:00/06:00 경계
  - 연장수당, 공휴일 수당 각 케이스
- **스케줄 추천 엔진**
  - FLEXIBLE 독립 추천 — 인원 부족, 연속 근무 초과, 전원 불가 신청 케이스
  - FIXED+FLEXIBLE 결합 최소 인원 조건 검증 케이스
- **GPS 반경 검증 함수**
  - 경계값(정확히 100m), 반경 초과, 반경 미달 케이스
- **초대 링크 토큰**
  - 만료, 중복 사용, 유효 케이스
- **FIXED 자동 반영**
  - 변경 반영 시점별(즉시/다음 주/다음 달), 정기 휴무일 겹침, 법정 공휴일 겹침 케이스

### 통합/E2E 테스트 (Supertest)

- 희망 신청 → AI 추천 → 관리자 확정 → Push 알림 → 명세서 발급 전 과정
- 근태 수정 요청 → 관리자 승인 → 반영 흐름
- 1:1 교환 요청 → 24시간 만료 자동 취소 케이스
- 1:1 교환 요청 → 상대방 수락 → 관리자 승인 → 양측 스케줄 동기화

### 수동 확인 (업종별 시나리오)

- 카페 체인 3매장 / 직원 20명 / `FLEXIBLE` 근무 기준 주간 스케줄 편성
- 편의점 3개 점포 / 각 매장 직원 8명 / 전원 `FIXED` 근무 기준 스케줄 확인 및 급여 정산 (공휴일 포함)

---

## 2. 기술 구현 리스크

- **급여 계산 법적 정확성**: 수당 규칙 오류 시 신뢰·법적 리스크. 특히 주휴수당 결근 예외, 공휴일 수당 5인 기준.
- **스케줄 추천 엔진 제약 충돌**: 모든 제약 조건을 동시에 만족하는 배치가 없을 때의 처리 전략을 사전에 정의해야 한다.
- **FIXED cron job 충돌**: 변경 시점 처리, 정기 휴무일·공휴일 교차 처리, 이미 확정된 스케줄과의 충돌 설계 필요.
- **GPS 정확도**: 실내·건물 내 환경에서 20~50m 오차 발생. 기본 반경 100m로 여유 확보, 오류 시 수정 요청 흐름으로 보완.
