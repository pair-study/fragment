# PRD: 일감 — 스케줄부터 급여까지 관리하는 근무 플랫폼

> **일하는 모든 순간을 정확하고 투명하게**
>
> 소·중형 단일 매장부터 다점포 사업장까지, 근무 스케줄 편성과 급여 계산을 자동화하는 SaaS

---

## 1. 배경

### 현재 문제

- 업종마다 룰이 다른 스케줄(고정 요일제, 주단위 로테이션, 단기 집중형)을 수기로 맞추는 과정의 비효율.
- 다양한 근무 형태에 따른 주휴·야간·공휴일(특일) 등 복잡한 수당 계산에서 발생하는 휴먼 에러.
- 불투명한 급여 산정 기준으로 인한 관리자–근로자 간 정보 비대칭과 불신.

### 서비스 당위성

- **최저임금 인상·주 52시간 정착**: 수당 계산의 법적 정확성 부담이 높아졌고, 계산 실수 한 번이 노동 분쟁으로 이어질 수 있다.
- **다양한 운영 규모**: 단일 매장 소상공인부터 다점포 운영자까지, 매장 수와 무관하게 교대근무 관리의 복잡도가 공통적으로 높다.
- **기존 도구의 한계**:
  - 수기/엑셀: 매장 수가 늘거나 인원이 많아지면 주휴수당 합산·대타 조율이 한계에 부딪힌다.
  - 범용 스케줄러(구글 캘린더 등): 노동법 기반 수당 계산이 없고 다점포 집계가 불가능하다.
  - 대형 ERP(SAP, Oracle): 소·중형 사업자가 감당하기엔 비용·도입 기간이 과도하다.

### 관련 문서 / 레퍼런스

- Shiftee — https://shiftee.io/ko/scheduler
- 하우머치 (Howmuch) — 조직 생성/초대, 세금·4대보험 설정 흐름 참고
- Deputy, 7shifts — 글로벌 다점포 교대근무 SaaS 구조 참고

## 2. 목표

### 사용자가 무엇을 할 수 있어야 하는가

- **관리자**: AI 추천으로 주간 스케줄 초안을 자동 생성하고, 근태·급여를 한 곳에서 관리한다.
- **근로자**: 희망 근무를 앱에서 신청하고, 확정 스케줄·대타·급여 명세를 투명하게 확인한다.
- **공통**: 수당이 자동 계산되어, 산정 기준이 양측에 동일하게 보인다.

### 정량 목표

- 주간 스케줄 편성 시간 **70% 이상 단축** (AI 자동 추천 대비 수기 편성 기준)
- 급여 계산 오류 **0 지향** (주휴·야간·연장 수당 자동화)
- 관리자–근로자 간 **급여 정산 분쟁 감소**

---

## 3. 대상 사용자

> 양면(two-sided) 제품 — 관리자와 근로자 모두 핵심 사용자이며, 구매 결정은 관리자가 한다.

### 관리자(Manager)

카페·치킨 체인(F&B), 학원·학원 그룹(교육), 병원·의원·요양원(의료), 편의점·물류 허브(서비스) 등 교대/시간제 근무가 있는 소·중형 단일 매장 또는 다점포 사업장. 다점포 관리자는 조직 스위칭으로 여러 매장을 한 계정에서 관리한다.

### 근로자(Worker)

- 다양한 형태의 교대/시간제 스케줄을 소화하는 근로자: 단기 스태프, 파트타이머 등.
- **한 명의 근로자가 여러 조직(매장)에 동시에 소속**될 수 있다 (투잡 등).
- 카카오 또는 네이버 소셜 로그인으로 가입하고, Expo 네이티브 앱(iOS·Android)에서 모든 기능을 사용한다.

---

## 4. 범위

> 페이즈 분류 기준: "이 기능 없이 핵심 루프(희망 신청 → 스케줄 확정 → 급여 정산)가 돌아가는가"

### Phase 1 — MVP: 핵심 서비스 루프 + 전체 플랫폼

**관리자 (`apps/web`, 데스크탑 전용 — 반응형 미지원)**

- [ ] 계정 및 조직 관리 (이메일+비밀번호 가입, 조직 CRUD, 다중 조직 스위칭)
- [ ] 인력 관리 (근로자 초대 링크, 스케줄 타입·임금명세서 템플릿 지정, 퇴사 처리)
- [ ] 스케줄 자동 추천 (규칙 기반 constraint satisfaction) + 수동 조정 + 확정
- [ ] 근태 확인·확정 (GPS 출퇴근 체크, 지각·연장 하이라이팅, 수정 요청 승인, 관리자 직접 입력)
- [ ] 급여 계산 (시급×근무시간 + 주휴·야간·연장·공휴일 수당) + 명세서 발급

**근로자 (`apps/app`, Expo 네이티브 앱 — iOS·Android)**

- [ ] 카카오 / 네이버 소셜 로그인
- [ ] 다중 조직 소속 및 전환
- [ ] 희망 근무 신청 (불가/제약 입력 방식)
- [ ] 확정 스케줄 확인
- [ ] GPS 기반 출퇴근 체크 (버튼 방식)
- [ ] 근태 수정 요청
- [ ] 급여 명세 확인 + 근태 서명/동의
- [ ] 1:1 스케줄 교환 요청 및 수락/거절
- [ ] Push 알림 (Expo Notifications) — 스케줄 확정·변경, 교환 요청, 퇴근 미처리 등

**인프라**

- [ ] AWS EC2 (NestJS API 서버)
- [ ] AWS S3 + CloudFront (Next.js 정적 호스팅)
- [ ] GitHub Actions CI/CD (테스트 자동화 + 자동 배포)

### Phase 2 — 고도화

- [ ] 관리자 웹 반응형 지원 (태블릿·모바일에서 관리자 접근 가능)
- [ ] 다점포 통합 뷰 (없으면 매장별로 따로 확인 가능)
- [ ] 조직 이전 기능 (관리자 탈퇴 시 다른 관리자 계정으로 조직 이전)
- [ ] 스케줄 알고리즘 고도화 (fairness — 근로자 간 균등 배분)

### 이번 작업에 포함하지 않음

- [ ] 4대보험/세무 신고 연동 (외부 기관 전송)
- [ ] 급여 실지급 (이체/송금) 연동
- [ ] WiFi 기반 체크인 (GPS 불가 대체 수단)
- [ ] 다점포 간 스케줄 교환
- [ ] 다국어/해외 노동법 대응

## 5. 사용자 흐름

### 흐름 A — AI 스케줄 편성 (관리자)

1. 근로자들이 **Expo 앱**에서 관리자가 설정한 **마감 기한** 내에 **안되는 날/시간대를 입력**한다.
2. 관리자가 **시간대별 최소 인원 조건**과 제약 조건을 확인한다.
3. 시스템이 `FLEXIBLE` 근로자 불가/제약 + `FIXED` 고정 스케줄 + 제약 조건을 분석해 **최적 스케줄 초안을 규칙 기반으로 추천**한다.
4. 시스템은 충족하지 못한 제약 조건(인원 부족, 연속 근무 초과 등)을 **Explainable UI로 하이라이팅**한다.
5. 관리자가 초안을 검토·조정하고 **확정**하면, 근로자에게 **Expo Push 알림**이 발송된다.

### 흐름 B — 근로자 근태 & 스케줄 교환

1. 근로자가 Expo 앱에서 GPS 반경(기본 100m) 내 위치 확인 후 **출근 버튼을 눌러 출근 체크**한다.
2. 근무 종료 후 동일하게 **퇴근 버튼을 눌러 퇴근 체크**한다.
   - 예정 시각 대비 지각·연장이 발생하면 관리자 화면에 **하이라이팅**으로 표시된다.
   - 퇴근 미처리 시 예정 퇴근 시간 +30분, +2시간 Push 알림 → 자정까지 미처리 시 "근태 미처리" 자동 전환.
3. GPS 불가 등 오류 발생 시 **근태 수정 요청 제출** → 관리자 승인/거절 → 승인 시 반영. 관리자 직접 입력도 가능 (감사 로그 기록 + 근로자 Push 알림).
4. 부여받은 스케줄 변경이 필요할 때:
   - 근로자가 상대방 근로자에게 **1:1 교환 요청** → 상대방 24시간 내 수락/거절 → 수락 시 관리자 최종 승인/거절 → 양측 스케줄 반영 및 Push 알림.

### 흐름 C — 급여 정산

1. 근로자가 Expo 앱에서 **근태 정보를 확인하고 서명/동의**한다 (오류 발견 시 수정 요청 제출).
2. 서명 즉시 해당 근로자의 급여 계산이 **자동으로 실행**된다. 확정 근태 기반으로 주휴·야간·연장·공휴일 수당이 계산되며, 여러 근로자가 동시에 서명한 경우 병렬로 처리된다.
3. 관리자가 산정 결과를 확인하고 **급여 명세서를 발급**한다.
4. 근로자가 Expo 앱에서 **명세서와 산정 기준을 확인**한다 (투명성).

## 6. 기능 요구사항

> **조직 관리 vs 인력 관리 분리 원칙**
>
> - **조직 관리** (FR-1): 매장 자체의 설정값 풀(pool)을 정의한다 — 임금명세서 템플릿 목록, 시간대별 최소 인원 조건, GPS 반경, 정기 휴무일, 법정 공휴일 정책, 스케줄 신청 기간, 1:1 교환 허용 여부.
> - **인력 관리** (FR-5): 근로자 개인에게 그 풀에서 값을 지정한다 — 어떤 템플릿을 쓸지, 스케줄 타입(FIXED/FLEXIBLE), FIXED의 경우 고정 스케줄.
>
> 관리자는 조직 설정에서 "사용 가능한 옵션"을 먼저 만들고, 인력 관리에서 근로자별로 "어떤 옵션을 쓸지" 지정한다.

### FR-1. 계정 및 조직 관리

#### 계정 관리

- FR-1.1 **관리자 계정**:
  - 가입 정보: 이름, 이메일, 비밀번호.
  - 비밀번호 재설정: 이메일 입력 → 재설정 링크 발송 (유효기간 30분) → 링크에서 새 비밀번호 설정.
  - 로그아웃.
  - 탈퇴: 계정 및 소속 조직은 소프트 딜리트 처리되며 로그인·기능 접근이 불가해진다. 근태·급여 이력은 근로기준법 제42조에 따라 3년간 보존된다.
- FR-1.2 **근로자 계정**:
  - 카카오 또는 네이버 소셜 로그인. `provider + provider_id` 조합으로 계정 식별.
  - 동일 이메일로 다른 소셜 플랫폼 가입 시도 시 기가입 플랫폼 안내 (예: "카카오 계정으로 이미 가입된 이메일입니다").
  - 로그아웃.
  - 탈퇴: 진행 중인 미정산 급여가 있으면 정산 완료 후 탈퇴 가능. 근태·급여 이력은 익명화 후 3년 보존.

#### 조직 관리

- FR-1.3 **조직 생성**:
  - 사업자번호 (필수) — 국세청 진위확인 API로 유효성 검증. 동일 사업자번호로 여러 조직 생성 허용 (법인 다지점 케이스 지원).
  - 업장명 (필수).
  - 위치 (필수) — 도로명주소 API로 주소 검색·자동완성.
  - **시간대별 최소 인원 조건**: 요일 그룹(평일/주말/개별 요일 선택) × 시간 범위(HH:MM~HH:MM) × 최소 인원 수. AI 스케줄 추천의 핵심 입력값.
  - **정기 휴무일 설정** (법정 공휴일과 별도):
    - 매주 특정 요일 휴무 (예: 매주 월요일).
    - 격주 특정 요일 휴무 (예: 2주마다 일요일).
    - 정기 휴무일로 설정된 날은 FIXED 자동 반영 시 스케줄 미생성, FLEXIBLE 추천 시 배정 제외.
  - **법정 공휴일 정책**:
    - "법정 공휴일에 FIXED 스케줄 자동 제외" on/off (기본: off).
    - 예외일 직접 지정 가능 — 특정 날짜 단위로 추가/제거 (예: 추석 전날은 근무 유지, 대체공휴일은 제외).
    - 한국 법정공휴일 목록 자동 관리.
  - **스케줄 신청 기간 설정** (FLEXIBLE 대상):
    - 스케줄 단위: 1주 / 2주 / 4주 / 직접 입력.
    - 신청 마감: 해당 기간 시작 N일 전까지 (기본값: 7일).
    - 조정 기간: 마감 후 관리자 수동 조정 기간 (기본값: 2일).
    - 자동 반복 여부: on/off (기본: off).
  - GPS 허용 반경 (기본 100m, 50m~300m 범위에서 설정).
  - 1:1 스케줄 교환 허용 여부 on/off.
  - 임금명세서 템플릿 목록 (선택, 생성 후 추가 가능).
- FR-1.4 **조직 수정**: 모든 조직 생성 항목 수정 가능.
- FR-1.5 **조직 삭제**: 소속 근로자 퇴사 처리 후 조직 삭제 가능. 근태·급여 데이터는 3년 보존.
- FR-1.6 **다중 조직 관리**: 관리자 1명이 여러 조직을 한 계정으로 운영·스위칭.

### FR-2. 스케줄 관리

#### 스케줄 상태

스케줄은 다음 세 가지 상태를 가진다.

- `DRAFT`: FLEXIBLE AI 추천 초안. 관리자가 아직 확정하지 않은 상태. 근로자에게 노출되지 않는다.
- `PUBLISHED`: 관리자 확정 완료. 근로자에게 Push 알림이 발송된 상태. FIXED 자동 반영 스케줄은 생성 시 즉시 `PUBLISHED`.
- `CANCELLED`: 교환 성사 등으로 취소된 스케줄. 이력 보존을 위해 삭제하지 않고 유지한다.

- FR-2.1 **희망 근무 신청** (`FLEXIBLE` 근로자, 불가/제약 입력 방식):
  - 기본값은 "모든 날 근무 가능"이며, 근로자가 **안되는 경우만 입력**한다.
  - 신청 기간이 오픈되면 해당 기간의 모든 날짜에 대해 '근무 가능' 상태의 레코드가 자동 생성된다. 근로자는 변경이 필요한 날짜만 수정하며, 미수정 레코드는 '근무 가능'으로 유지된다.
  - 조직 설정의 신청 기간이 오픈되면 근로자가 Expo 앱의 주간 캘린더에서 날짜별로 상태를 설정한다:
    - **불가**: 해당 날 완전히 근무 불가 (hard constraint — AI가 배정하지 않음).
    - **시간 제약**: 특정 시간 이후/이전만 가능 (soft constraint — 해당 시간대 내에서만 배정). 30분 단위 드롭다운 선택.
  - 미입력 날짜는 하루 전체 근무 가능으로 처리된다.
  - 마감 기한 내 수정 가능. 마감 후 미신청 근로자는 해당 기간 전체 근무 가능으로 처리.
- FR-2.2 **스케줄 타입**: 근로자별로 `FIXED`(고정) 또는 `FLEXIBLE`(유동) 타입 지정. 한 조직 내 혼용 가능.
  - `FIXED`: 관리자가 인력 관리(FR-5.1)에서 요일별 고정 스케줄을 입력하면 캘린더에 자동 반영된다.
    - FIXED만 있는 조직: 월 단위로 자동 생성.
    - FLEXIBLE과 혼용인 조직: 조직 설정의 스케줄 단위(1주/2주/4주 등)에 맞춰 자동 생성.
    - 변경 시 반영 시점 선택 (즉시 다음 근무 / 다음 주 / 다음 달).
  - `FLEXIBLE`: 근로자의 희망 신청(FR-2.1) 기반 AI 추천 대상.
- FR-2.3 **스케줄 자동 추천** (규칙 기반 constraint satisfaction):
  - `FIXED` 근로자 스케줄은 자동 반영으로 이미 캘린더에 독립적으로 올라와 있는 상태.
  - `FLEXIBLE` 근로자는 자신의 불가/제약 신청 + 노동법 제약(주 52시간, 연속 근무 제한, 주휴수당 발생 조건)을 기반으로 독립적으로 AI 추천을 받는다.
  - 출력: FLEXIBLE 스케줄 초안 + FIXED+FLEXIBLE 결합 결과를 최소 인원 조건에 검증한 Explainable UI ("오픈 시간대 최소 인원 충족 ✅ / 김철수 주 40시간 초과 위험 ⚠️ / 주말 최소 인원 부족 ❌").
- FR-2.4 **스케줄 확정 및 알림**: 관리자 확정 → 근로자에게 Expo Push 알림.
- FR-2.5 **1:1 스케줄 교환**:
  - 신청자 요청 → 상대방 **24시간 내** 수락/거절 (미응답 시 자동 취소. 교환 대상 근무일까지 24시간 미만이면 유효기간 자동 단축) → (수락 시) 관리자 최종 승인/거절 → 양측 스케줄 반영 및 Push 알림.
  - 교환은 **동일 조직 내**에서만 허용한다. 다점포 간 교환은 지원하지 않는다.
  - 교환 성사 시 기존 스케줄은 `CANCELLED` 처리되고 교환된 스케줄이 새로 생성된다.

### FR-3. 근태 관리

#### 근태 레코드 생성 방식

스케줄이 `PUBLISHED` 상태로 확정되면 해당 근로자의 근태 레코드가 `EXPECTED` 상태로 자동 생성된다. 이후 상태 전이는 다음과 같다.

- `EXPECTED` → 출근 체크인 시 `PRESENT`
- `PRESENT` → 퇴근 체크아웃 완료 시 `COMPLETED`
- `EXPECTED` 또는 `PRESENT` → 자정까지 미처리 시 `UNPROCESSED` (자동 전환)

- FR-3.1 **GPS 기반 출퇴근 체크**:
  - 위치 정보 수집 동의: 앱 최초 실행 시 수집.
  - 근로자가 허용 반경 내에서 출근/퇴근 버튼을 눌러 체크인. 다중 조직 근로자는 앱에서 조직 전환 후 해당 매장 반경 내에서 체크인.
  - 기본 허용 반경: 100m. 관리자가 조직별로 50m~300m 범위에서 설정 가능 (FR-1.3).
- FR-3.2 **지각·연장 하이라이팅**: 예정 스케줄과 실제 출퇴근 시간이 다를 경우 관리자 화면에서 해당 블록을 눈에 띄게 표시.
  - 지각: 예정 출근 시각보다 늦은 체크인.
  - 연장: 퇴근 체크아웃 시 근로자가 '연장 근무' 여부를 선택할 수 있다. 연장 선택 시 실제 업무 종료 시각을 별도 입력한다(버튼을 누른 시각과 무관하게 정확한 근무 시간 기록). 연장 선택 여부와 입력된 종료 시각이 관리자 화면에 하이라이팅으로 표시된다. 별도 사전 합의 기록은 관리하지 않는다.
  - 예정 퇴근 시간 기준: `FIXED`는 고정 스케줄, `FLEXIBLE`은 확정 스케줄 참조.
- FR-3.3 **퇴근 미처리 자동화**:
  - 예정 퇴근 시간 +30분: 근로자에게 Push 알림 발송.
  - 예정 퇴근 시간 +2시간: 2차 Push 알림 발송.
  - 자정(00:00)까지 미처리: "근태 미처리" 상태 자동 전환, 관리자에게 Push 알림.
- FR-3.4 **근태 수정 요청**: 근로자 제출 → 관리자 승인/거절 → 승인 시 반영. 감사 로그(audit trail) 보존.
- FR-3.5 **관리자 직접 입력**: 앱 오류 등 예외 상황 시 관리자가 근로자 출퇴근 시간을 직접 입력 가능. 감사 로그에 "관리자 직접 입력"으로 별도 기록, 근로자에게 변경 내용 Push 알림 발송.
- FR-3.6 **근태 확정 및 서명**: 급여 계산 전 근로자 서명/동의 요청. 서명은 동의 여부(boolean)와 타임스탬프로 저장한다.

### FR-4. 급여 계산 엔진

임금명세서 템플릿 항목 (하우머치 기반, 조직 관리에서 생성 후 근로자별 지정):

| 항목        | 세부 내용                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------- |
| 세금·보험   | 3.3% 원천징수 / 소득세+4대보험 / 4대보험 전체 / 고용보험만 중 선택                          |
| 월급일      | 주기(월/2주/주/당일) + 기준 날짜 또는 요일. 당일은 근무한 날 당일 지급(일용직 형태, 매일 정산).  |
| 급여 기준   | 시급 / 일급                                                                                 |
| 휴무 처리   | 유급 / 무급 선택                                                                            |
| 결근 처리   | 주휴수당 제외 여부 (무단 결근 시 해당 주 주휴수당 미지급. 유급 처리된 결근은 개근으로 처리) |
| 주휴수당    | 기준 주 시작 요일 + 소정근로시간 설정. 주 15시간 미만 근로자는 자동 제외                    |
| 야간수당    | 비율(150% / 200% / 250% / 직접입력) + 야간 시간 범위 설정 (기본: 22:00~06:00). 시간 범위는 템플릿 단위로 설정.  |
| 연장수당    | 비율(150% / 200% / 250% / 직접입력) + 기준 시간 설정                                        |
| 공휴일 수당 | on/off + 비율(150% / 200% / 250% / 직접입력). 5인 이상 사업장은 on 권장                     |
| 기타        | 상여, 비과세                                                                                |

- FR-4.1 위 템플릿 기반으로 확정 근태 데이터를 자동 계산.
- FR-4.2 **급여 계산 트리거**: 근로자가 근태에 서명·동의하면 해당 근로자의 급여 계산이 자동으로 실행된다. 여러 근로자의 서명이 동시에 완료된 경우 병렬로 처리된다.
- FR-4.3 급여 명세서 발급 (항목별 계산 내역 포함).
- FR-4.4 급여 계산 감사 로그 — 계산 기준 및 변경 이력 추적.

### FR-5. 인력 관리

- FR-5.1 **신규 등록**:
  - 초대 링크 공유 → 근로자 소셜 로그인 → 조직 자동 연결. 초대 링크는 다수가 동시에 사용 가능하며, 유효기간은 7일이다. 관리자는 언제든 기존 링크를 무효화하고 재발급할 수 있다.
  - 관리자가 스케줄 타입(FIXED/FLEXIBLE) 지정.
  - **`FIXED` 선택 시 고정 스케줄 입력**:
    - 요일별 근무 시간 설정: 시작 시간 / 종료 시간.
    - 휴게 시간 포함 여부 체크 → 체크 시 휴게 시간(시작·종료) 추가 입력.
    - 입력된 고정 스케줄이 캘린더에 자동 반영 (FIXED만 있는 조직: 월 단위, 혼용 조직: 스케줄 단위에 맞춰 생성). 변경 시 반영 시점 선택 (즉시 다음 근무 / 다음 주 / 다음 달).
  - 임금명세서 템플릿 지정: 조직에 등록된 템플릿 중 선택. 템플릿이 없으면 조직 관리(FR-1.4)에서 먼저 생성.
- FR-5.2 **퇴사 처리**: 소프트 딜리트. 로그인 불가·스케줄 편성 제외. 근태·급여 데이터는 3년 보존 (근로기준법 제42조).
- FR-5.3 **퇴직자 데이터 조회**: 관리자가 퇴사 이후에도 해당 근로자의 근태·급여 이력 조회 가능.
- FR-5.4 **근로자 다중 조직**: 근로자 1명이 여러 조직에 소속 가능 (투잡 등). 각 조직 소속은 독립적으로 관리되며, 시급·스케줄 타입(FIXED/FLEXIBLE)·임금명세서 템플릿은 조직별로 별도 지정한다. Expo 앱에서 조직 전환으로 각 조직의 스케줄·근태·급여를 별도 확인한다.

### FR-6. 대시보드

- FR-6.1 **관리자** (`apps/web`, 데스크탑 전용 — 반응형 미지원):
  - 스케줄 관리: 희망 신청 취합 → AI 추천 → 확정, 1:1 교환 승인/거부.
  - 근로자 관리: 초대·등록·퇴사, 근태 확인·지각연장 하이라이팅·수정 승인·직접 입력, 급여 계산·명세서 발급.
  - 조직 관리: 임금명세서 템플릿 CRUD, 시간대별 최소 인원 조건, 정기 휴무일, 공휴일 정책, 조직 설정.
- FR-6.2 **근로자** (`apps/app`, Expo 네이티브 앱):
  - 조직 전환, 희망 근무 신청, 확정 스케줄 확인, GPS 출퇴근 체크, 근태 수정 요청, 급여 명세 확인 및 서명, 1:1 교환 요청, Push 알림 수신.

## 7. 비기능 요구사항

- **성능**:
  - 스케줄 화면 LCP(최대 콘텐츠 풀인트) **2.5초 이하**
  - AI 스케줄 추천 응답 **3초 이하** (20명·5매장 기준)
  - 급여 계산 응답 **1초 이하**
- **플랫폼**:
  - 관리자: 데스크탑 웹 (`apps/web`, 반응형 미지원)
  - 근로자: Expo 네이티브 앱 (`apps/app`, iOS·Android)
- **접근성**: 모바일 최소 폰트 14px, 명도 대비 WCAG AA 기준.
- **보안**: 급여·개인정보 암호화, 조직 간 데이터 격리(Row-level security), 사업자번호 검증.
- **정확성/규정**: 노동법 기반 수당 계산 정확성 — 최저임금·주휴수당·공휴일 규정 변경 시 엔진 업데이트 대응.
- **로깅/모니터링**: 급여 계산 감사 로그, 스케줄 변경 이력 추적, 관리자 직접 입력 이력 추적.

  - 스케줄 추천 엔진 — FLEXIBLE 독립 추천(인원 부족, 연속 근무 초과, 전원 불가 신청 케이스), FIXED+FLEXIBLE 결합 최소 인원 조건 검증 케이스
  - GPS 반경 검증 함수 — 경계값(정확히 100m), 반경 초과, 반경 미달 케이스
  - 초대 링크 토큰 — 만료, 중복 사용, 유효 케이스
  - FIXED 자동 반영 — 변경 반영 시점별(즉시/다음 주/다음 달), 정기 휴무일 겹침, 법정 공휴일 겹침 케이스

  - 근태 수정 요청 → 관리자 승인 → 반영 흐름
  - 1:1 교환 요청 → 24시간 만료 자동 취소 케이스
  - 1:1 교환 요청 → 상대방 수락 → 관리자 승인 → 양측 스케줄 동기화
- **수동 확인 (업종별 시나리오)**:
  - 카페 체인 3매장 / 직원 20명 / `FLEXIBLE` 근무 기준 주간 스케줄 편성
  - 편의점 3개 점포 / 각 매장 직원 8명 / 전원 `FIXED` 근무 기준 스케줄 확인 및 급여 정산 (공휴일 포함)

## 9. 리스크

- 급여 계산의 **법적 정확성** 부담 (수당 규칙 오류 시 신뢰·법적 리스크). 특히 주휴수당 결근 예외, 공휴일 수당 5인 기준.
