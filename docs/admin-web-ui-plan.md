# 관리자 웹 UI 작업 계획

이 문서는 관리자 웹(`apps/web`)에서 앞으로 만들어야 할 페이지와 각 페이지에 들어갈 내용을 정리한다. 기준 문서는 `docs/SPEC.md`이며, 현재까지 확정한 관리자 웹 IA 결정을 함께 반영한다.

## 현재 작업 범위

- 현재 단계는 관리자 웹 와이어프레임 UI 설계와 화면 구조 확정에 집중한다.
- 실제 상태 관리, mock 흐름 연결, API 연동, 저장 동작, 라우팅 후처리는 아직 구현 범위에 포함하지 않는다.
- 화면 확인에 필요한 예시 텍스트와 예시 데이터는 각 페이지 내부에서만 사용한다.
- 여러 페이지를 공통 상태로 연결하는 mock 데이터는 두지 않는다.
- 와이어프레임 UI 범위를 모두 확인한 뒤, 상태 설계와 API 연동 계획은 별도 단계로 다시 잡는다.

## 확정 IA 원칙

- 로그인 후 주요 메뉴는 `홈`, `근무일정`, `근태관리`, `급여정산`, `인력관리`, `조직관리`로 구성한다.
- `요청내역`은 독립 사이드바 메뉴로 두지 않는다. 근태 수정 요청은 `근태관리` 안에서 처리한다.
- 다중 조직 전환은 상단바 조직 스위칭으로 처리한다.
- `조직관리`는 조직 카드 목록이 아니라 현재 선택된 조직의 설정을 관리하는 페이지로 둔다.
- 조직이 0개일 때만 조직 없음 빈 상태와 조직 생성 CTA를 보여준다.
- 홈 대시보드는 단순 현황 숫자가 아니라 관리자가 바로 처리할 수 있는 항목 중심으로 구성한다.
- 계정 관련 기능은 상단바 계정 메뉴에서 `계정 설정`, `로그아웃`으로 진입한다.

## 작업 순서

### 0. 구현 원칙 재정리

상태: 진행 중

목표:
- UI 와이어프레임만 먼저 모두 만든다.
- 조직 유무, 선택 조직, 처리 건수 같은 운영 상태는 아직 연결하지 않는다.
- 빈 상태와 일반 상태가 모두 필요하면 별도 미리보기 경로 또는 페이지 내부 예시 데이터로 확인한다.

후속 단계로 미루는 것:
- Zustand, TanStack Query, 서버 응답 기반 상태 연결
- 조직 생성 후 자동 이동/활성화 흐름
- 로그아웃, 저장, 삭제, 승인 같은 실제 액션 연결
- 조직 스위칭 동작

### 1. 로그인 후 공통 레이아웃

상태: 1차 구현 완료, UI 와이어프레임 기준 유지

만들 페이지/영역:
- 공통 관리자 shell
- 사이드바
- 상단바
- 계정 설정

들어갈 내용:
- 사이드바 메뉴: 홈, 근무일정, 근태관리, 급여정산, 인력관리, 조직관리
- 상단바: 현재 조직 표시, 조직 스위칭, 조직 추가 진입
- 계정 메뉴: 관리자 이름/이메일, 계정 설정, 로그아웃
- 조직이 없을 때 조직 의존 메뉴 비활성화

남은 작업:
- 와이어프레임 기준으로 레이아웃 밀도와 간격 정리
- 추후 상태 연결 단계에서 실제 조직 목록 API 연동
- 추후 상태 연결 단계에서 현재 선택 조직 상태 관리
- 추후 기능 연결 단계에서 로그아웃 동작 연결
- 추후 기능 연결 단계에서 계정 탈퇴 API 연결

### 2. 조직 없음 홈

상태: 1차 구현 완료

경로:
- `/home`

들어갈 내용:
- 조직 등록 전 안내
- 조직 등록 CTA
- 조직 등록에 필요한 정보 안내
- 조직 등록 이후 다음 업무 흐름 안내

제외할 내용:
- 현재 근무 중 0명 카드
- 미처리 근태 0건 카드
- 확정 대기 스케줄 0건 카드
- 급여 발급 대기 0건 카드

이유:
- 조직이 없는 상태에서는 운영 데이터가 없으므로 0건 카드가 행동으로 이어지지 않는다.
- 빈 상태의 핵심 행동은 조직 등록 하나로 충분하다.

남은 작업:
- 조직이 있는 상태의 홈 대시보드 와이어프레임 추가
- 처리 필요 항목 우선순위와 카드 구조 확정
- 추후 기능 연결 단계에서 실제 운영 데이터 연동

조직이 있는 상태의 홈 대시보드 기준:
- `처리 필요`와 `마감 임박` 중심으로 구성한다.
- 우선 카드 후보:
  - 미처리 근태
  - 수정 요청 대기
  - 확정 대기 스케줄
  - 급여 발급 대기
- 보조 섹션 후보:
  - 근무 불가 신청 마감 임박
  - 정산 기간 종료 후 서명 대기
  - 오늘 예정 근무
  - 미출근/지각
  - 퇴근 누락

메인 카드에서 제외할 후보:
- 현재 근무 중 인원

이유:
- 현재 근무 중 인원은 실시간 모니터링 정보로는 의미가 있지만, 관리자 홈의 1차 액션으로 이어지는 정보는 아니다.
- 필요하면 `오늘 운영` 보조 섹션에 작게 배치한다.

### 3. 조직 생성

상태: 1차 구현 중

경로:
- `/organizations/new`

들어갈 내용:
- 사업자등록번호
- 사업자등록번호 진위 확인
- 조직명
- 도로명 주소 검색
- 상세주소
- GPS 허용 반경
- 근무 유형: 고정 근무, 신청 근무, 둘 다
- 조직 휴무일: 매주, 격주, 특정일
- 저장/취소 액션

UX 기준:
- 첫 조직 생성은 온보딩 흐름의 핵심 액션이다.
- 생성 완료 후에는 현재 조직 컨텍스트가 생긴 상태로 `/home` 또는 `/organizations`로 이동한다.
- 사업자등록번호는 생성 후 변경 불가 항목으로 처리한다.

남은 작업:
- 입력 UI 밀도와 안내 문구 정리
- 추후 기능 연결 단계에서 주소 검색 API 연결
- 추후 기능 연결 단계에서 사업자등록번호 진위 확인 API 연결
- 추후 기능 연결 단계에서 생성 완료 후 이동 경로 확정

### 4. 조직관리

상태: 와이어프레임 구조 확정 중

경로:
- `/organizations`
- `/organizations/empty` (조직 없음 상태 확인용)

들어갈 내용:
- 현재 선택 조직의 기본 정보
  - 조직명
  - 사업자등록번호
  - 주소
  - GPS 허용 반경
  - 근무 유형
- 조직 휴무일
  - 설정된 휴무일 목록
  - 휴무일 추가
  - 휴무일 수정
  - 휴무일 삭제
- 조직 삭제
  - 삭제 안내
  - 재직 근무자가 있으면 삭제 차단

제외할 내용:
- 조직 카드 목록
- 근무자 수
- 현재 근무 중 인원
- 처리 필요 건수
- 주소 중심 카드

이유:
- 위 정보들은 조직 전환 또는 운영 대시보드에는 의미가 있을 수 있지만, 조직 설정 화면에서 직접적인 수정 행동으로 이어지지 않는다.
- 다중 조직 전환은 상단바에서 처리하므로 `/organizations`는 현재 조직 설정에 집중한다.

남은 작업:
- 조직 없음 상태 UI와 조직 설정 UI 톤 정리
- 조직 설정 읽기 상태와 수정 상태 레이아웃 정리
- 기존 조직 카드 UI 제거 여부 최종 확인
- 조직 삭제 경고 영역 정보량 조정

### 5. 인력관리

상태: 와이어프레임 1차 구현 중

경로:
- `/members`
- `/members/new`
- `/members/:workerId`

들어갈 내용:
- 근무자 목록
  - 이름
  - 사번
  - 재직/퇴직 상태
  - 스케줄 타입
  - 임금명세서 템플릿 지정 여부
- 근무자 등록
  - 이름
  - 사번은 저장 후 서버 자동 발급
  - 스케줄 타입: FIXED, FLEXIBLE
  - 입사일
  - 전화번호
  - 임금명세서 템플릿
- 근무자 상세
  - 기본 정보
  - 사번 조회
  - 조직 연결 상태
  - 임금명세서 템플릿 지정
- FIXED 근무 설정
  - 요일별 근무 여부
  - 시작/종료 시간
  - 휴게 시간
  - 변경 반영 시점
- 퇴사 처리
  - 미정산 급여가 있으면 차단
  - 확정된 미래 스케줄 취소 후 퇴사 처리

권장 작업 순서:
1. 근무자 목록
2. 근무자 등록 폼
3. 근무자 상세/수정
4. FIXED 근무 설정
5. 퇴사 처리 다이얼로그

UI 기준:
- 등록 화면에서는 사번 입력 필드를 제공하지 않는다.
- 등록 화면에는 "사번은 저장 후 자동 발급돼요" 안내만 표시한다.
- 목록과 상세 화면에서만 발급된 사번을 조회한다.
- 수정 화면에서도 사번은 변경할 수 없는 읽기 전용 정보로 표시한다.

## 전체 권장 구현 순서

### 1차: UI 와이어프레임 범위

1. 조직관리 재정리
   - 조직 카드 UI 제거
   - 현재 조직 설정 페이지로 변경
   - 조직 없음 상태와 조직 설정 미리보기 분리

2. 조직이 있는 상태의 홈 대시보드
   - 처리 필요와 마감 임박 중심 카드 구성
   - 운영 지표는 보조 섹션으로 제한

3. 인력관리
   - 목록 빈 상태
   - 등록 폼
   - 상세 화면
   - 퇴사 처리 다이얼로그

4. 근무일정
   - 캘린더 빈 상태
   - 사이클 생성
   - 배치/확정 화면 구조

5. 근태관리
   - 전체 목록
   - 처리 필요
   - 수정 요청
   - 관리자 직접 입력

6. 급여정산
   - 정산 목록 빈 상태
   - 발급 대기
   - 템플릿 관리

### 2차: 상태/기능 연결 단계

1. 조직 생성 완료 이후 상태 연결
2. 상단바 조직 전환 상태 연결
3. 홈 운영 데이터 연결

## 보류하거나 나중에 결정할 사항

- 이메일 변경 기능은 현재 SPEC에 없으므로 구현하지 않는다.
- `요청내역` 독립 메뉴는 현재 범위에서 만들지 않는다.
- 조직 목록 카드는 조직관리 화면에 두지 않는다.
- 조직 전환 정보는 상단바 드롭다운에서 처리한다.
- 대시보드성 운영 지표는 `/home`에서 다룬다.
- 실제 API 연동 전까지 mock 데이터는 UI 흐름 검증용으로만 사용한다.
