## FR-1. 계정 및 조직 관리

---

### FR-1.1 관리자 계정

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 |
| 플랫폼 | 웹 (`apps/web`) |
| 우선순위 | P1 |

#### 사용자 시나리오

카페를 운영하는 관리자가 처음 서비스에 접속해 계정을 만들고 조직을 생성하려 한다. 또는 비밀번호를 잊어버린 관리자가 이메일로 재설정을 요청한다.

#### 기능 상세 설명

**가입**

| 입력값 | 유효성 조건 |
|---|---|
| 이름 | 필수, 1자 이상 |
| 이메일 | 필수, 이메일 형식, 중복 불가 |
| 비밀번호 | 필수, 8자 이상, 영문+숫자 조합 |

- 출력: 계정 생성 완료 후 로그인 상태로 대시보드 이동.

**로그인**

| 입력값 | 유효성 조건 |
|---|---|
| 이메일 | 필수 |
| 비밀번호 | 필수 |

- 출력: JWT 발급 후 대시보드 이동.

**비밀번호 재설정**

| 단계 | 입력값 | 처리 |
|---|---|---|
| 1 | 이메일 | 가입된 이메일이면 재설정 링크 발송 |
| 2 | 새 비밀번호 (링크 접속 후) | 링크 유효기간 30분 이내 |

- 출력: 비밀번호 변경 완료 후 로그인 페이지로 이동.

**탈퇴**

- 소속 조직 및 계정 소프트 딜리트. 로그인·기능 접근 불가.
- 근태·급여 이력은 근로기준법 제42조에 따라 3년 보존.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 이미 가입된 이메일로 가입 시도 | "이미 사용 중인 이메일입니다" 안내 |
| 로그인 실패 (이메일·비밀번호 불일치) | "이메일 또는 비밀번호가 올바르지 않습니다" 안내 (구체적인 원인 노출 금지) |
| 재설정 링크 30분 초과 접근 | "만료된 링크입니다. 재설정을 다시 요청해 주세요" 안내 |
| 재설정 링크 재사용 | 1회 사용 후 무효화, 동일 메시지 반환 |

### FR-1.2 근로자 계정

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 |
| 플랫폼 | 앱 (`apps/app`) |
| 우선순위 | P1 |

#### 사용자 시나리오

편의점 아르바이트생이 관리자에게 초대 링크를 받아 카카오 소셜 로그인으로 가입한다. 이미 다른 매장에서 네이버로 가입한 이력이 있어 플랫폼 혼동이 발생한다.

#### 기능 상세 설명

**소셜 로그인 (가입·로그인 통합)**

| 입력값 | 처리 |
|---|---|
| 카카오 OAuth | `provider=kakao`, `provider_id` 조합으로 계정 식별 |
| 네이버 OAuth | `provider=naver`, `provider_id` 조합으로 계정 식별 |

- 최초 소셜 로그인 시 계정 자동 생성.
- 재로그인 시 기존 계정 매칭.
- 출력: JWT 발급 후 홈 화면(조직 목록) 이동.

**탈퇴**

- 진행 중인 미정산 급여(서명 완료 후 명세서 미발급 상태)가 있으면 정산 완료 후 탈퇴 가능.
- 계정 소프트 딜리트. 근태·급여 이력은 익명화 후 3년 보존.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 동일 이메일로 다른 소셜 플랫폼 가입 시도 | "카카오(또는 네이버) 계정으로 이미 가입된 이메일입니다" 안내, 기가입 플랫폼으로 유도 |
| 소셜 플랫폼 OAuth 오류 | "소셜 로그인에 실패했습니다. 잠시 후 다시 시도해 주세요" 안내 |
| 미정산 급여가 있는 상태에서 탈퇴 시도 | 정산 완료 전까지 탈퇴 불가 안내 |

### FR-1.3 조직 생성

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 |
| 플랫폼 | 웹 |
| 우선순위 | P1 |

#### 사용자 시나리오

카페 프랜차이즈 본사 관리자가 신규 지점을 시스템에 등록하면서 위치, 최소 인원 조건, 급여 템플릿을 함께 설정한다.

#### 기능 상세 설명

**입력값**

| 필드 | 필수 여부 | 유효성 조건 |
|---|---|---|
| 사업자번호 | 필수 | 국세청 진위확인 API 검증 통과. 동일 사업자번호 중복 생성 허용 (다지점 지원) |
| 업장명 | 필수 | 1자 이상 |
| 위치 | 필수 | 도로명주소 API 자동완성으로 선택 |
| 시간대별 최소 인원 조건 | 선택 | 요일 그룹 × 시간 범위 × 최소 인원 수. 복수 설정 가능 |
| 정기 휴무일 | 선택 | 매주 특정 요일 또는 격주 특정 요일 선택 |
| 법정 공휴일 정책 | 선택 | FIXED 스케줄 자동 제외 on/off (기본 off). 예외일 직접 추가/제거 가능 |
| 스케줄 신청 기간 | 선택 | 단위(1주/2주/4주/직접 입력), 마감 N일 전(기본 7일), 조정 기간(기본 2일), 자동 반복 on/off |
| GPS 허용 반경 | 선택 | 50m~300m (기본 100m) |
| 1:1 교환 허용 여부 | 선택 | on/off |
| 임금명세서 템플릿 | 선택 | 조직 생성 후 별도 추가 가능 |

- 출력: 조직 생성 완료 후 조직 대시보드로 이동.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 유효하지 않은 사업자번호 | "유효하지 않은 사업자번호입니다" 안내, 저장 차단 |
| 국세청 API 호출 실패 | 재시도 안내. 3회 실패 시 수동 확인 후 등록 안내 |
| 위치 주소 미선택(직접 입력) | 도로명주소 API 결과 목록에서만 선택 가능, 자유 입력 불가 |

## FR-2. 스케줄 관리

> **스케줄 상태**: `DRAFT` (FLEXIBLE 추천 초안, 관리자 미확정) → `PUBLISHED` (관리자 확정, Push 알림 발송). FIXED 자동 반영 스케줄은 생성 즉시 `PUBLISHED`. 교환 취소된 스케줄은 `CANCELLED` (이력 보존, 삭제 안 함).

---

### FR-2.1 희망 근무 신청

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 (FLEXIBLE 타입) |
| 플랫폼 | 앱 |
| 우선순위 | P1 |

#### 사용자 시나리오

파트타임 대학생 근로자가 이번 주 수요일은 시험이라 근무 불가, 목요일은 오후 2시 이후만 가능하다고 앱에서 입력한다.

#### 기능 상세 설명

**레코드 사전 생성**

- 조직의 스케줄 신청 기간이 오픈되면, 해당 기간의 모든 날짜에 대해 근로자별 '근무 가능' 상태 레코드가 자동 생성된다.
- 근로자는 변경이 필요한 날짜만 수정하며, 미수정 레코드는 '근무 가능'으로 유지된다.

**입력값 (날짜별 상태 설정)**

| 상태 | 의미 | 제약 유형 |
|---|---|---|
| 근무 가능 (기본값) | 하루 전체 근무 가능 | 없음 |
| 불가 | 해당 날 완전 근무 불가 | Hard constraint (AI 배정 제외) |
| 시간 제약 | 특정 시간 이후/이전만 가능 | Soft constraint (해당 시간대 내 배정) |

- 시간 제약 선택 시: 가능 시작 시간 또는 가능 종료 시간 30분 단위 드롭다운으로 입력.
- 신청 기간 마감 전까지 수정 가능.

**출력**: 신청 내용 저장. 관리자 AI 추천 시 입력값으로 활용.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 마감 기한 이후 수정 시도 | 입력 UI 비활성화, "신청 기간이 마감됐습니다" 안내 |
| 신청 기간이 오픈되지 않은 상태 | "아직 신청 기간이 열리지 않았습니다" 안내 |

### FR-2.2 FIXED 스케줄 자동 반영

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 (설정), 근로자 (조회) |
| 플랫폼 | 웹 (설정), 앱 (조회) |
| 우선순위 | P2 |

#### 사용자 시나리오

매주 월·수·금 09:00~18:00 근무하는 고정 직원의 스케줄을 관리자가 시스템에 입력하면, 이후 매월 해당 패턴으로 스케줄이 자동 생성된다.

#### 기능 상세 설명

**입력값 (인력 관리 FR-5.1에서 설정)**

| 필드 | 내용 |
|---|---|
| 요일별 근무 여부 | 월~일 각각 on/off |
| 시작 시간 / 종료 시간 | HH:MM 형식 |
| 휴게 시간 | 포함 여부 체크. 체크 시 휴게 시작·종료 시간 추가 입력 |
| 변경 반영 시점 | 즉시 다음 근무 / 다음 주 / 다음 달 / 직접 입력 (날짜 지정) |

**자동 반영 규칙**

- FIXED만 있는 조직: 월 단위로 자동 생성.
- FIXED+FLEXIBLE 혼용 조직: 조직 설정의 스케줄 단위(1주/2주/4주 등)에 맞춰 생성.
- 생성된 스케줄은 즉시 `PUBLISHED` 상태.
- 정기 휴무일로 설정된 날: 스케줄 미생성.
- 법정 공휴일 정책 "FIXED 자동 제외" on인 경우: 공휴일 스케줄 미생성 (예외일 직접 지정 적용).

**출력**: 지정된 기간에 해당하는 `PUBLISHED` 상태 스케줄 레코드 생성.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 변경 반영 시점 "즉시"인데 이미 확정된 스케줄이 있을 경우 | 기존 PUBLISHED 스케줄을 CANCELLED 처리 후 새 스케줄 생성 |
| 정기 휴무일과 근무 요일이 겹칠 경우 | 해당 날짜 스케줄 미생성 |

### FR-2.3 스케줄 자동 추천

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 |
| 플랫폼 | 웹 |
| 우선순위 | P1 |

#### 사용자 시나리오

스케줄 신청 마감 후, 관리자가 "AI 추천 실행" 버튼을 누르면 FLEXIBLE 근로자들의 신청 데이터를 기반으로 최적 스케줄 초안이 생성된다.

#### 기능 상세 설명

**입력값 (시스템 자동 수집)**

| 데이터 | 출처 |
|---|---|
| FLEXIBLE 근로자 희망 신청 (불가/제약) | FR-2.1 |
| FIXED 근로자 확정 스케줄 | FR-2.2 |
| 시간대별 최소 인원 조건 | FR-1.3 조직 설정 |
| 노동법 제약 (주 52시간, 연속 근무 제한, 주휴수당 발생 조건) | 시스템 내장 |

**처리 규칙**

- FLEXIBLE 근로자: 불가(hard constraint) 날짜 배정 제외. 시간 제약(soft constraint)은 해당 시간대 내에서 배정.
- FIXED 스케줄은 이미 캘린더에 올라온 상태. FIXED+FLEXIBLE 결합 결과를 최소 인원 조건에 검증.

**출력 (Explainable UI)**

| 표시 | 의미 |
|---|---|
| ✅ | 해당 시간대 최소 인원 충족 |
| ⚠️ | 주 40시간 초과 위험 등 경고 |
| ❌ | 최소 인원 미충족 |

- 생성된 초안 스케줄 상태: `DRAFT`.
- 성능 목표: 20명·5매장 기준 3초 이하 응답.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 전원 불가 신청으로 배정 불가한 시간대 발생 | 해당 시간대 ❌ 하이라이팅 후 관리자에게 수동 조정 유도 |
| 모든 제약 조건을 동시에 만족하는 배치가 없을 경우 | 가장 많은 조건을 충족하는 배치 생성 후 미충족 조건 목록 표시 |
| 신청 기간 마감 후 미신청 근로자 | 해당 기간 전체 '근무 가능'으로 처리 후 추천 대상에 포함 |

### FR-2.4 스케줄 확정 및 알림

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 (확정), 근로자 (수신) |
| 플랫폼 | 웹 (확정), 앱 (알림 수신·조회) |
| 우선순위 | P1 |

#### 사용자 시나리오

AI 추천 초안을 검토한 관리자가 일부 시간대를 수동으로 조정한 뒤 확정 버튼을 누른다. 근로자들은 즉시 Push 알림을 받고 앱에서 확정 스케줄을 확인한다.

#### 기능 상세 설명

**관리자 동작**

1. DRAFT 상태 스케줄 조회 (캘린더 또는 목록).
2. 필요 시 개별 스케줄 수동 조정 (시간 변경, 근로자 교체).
3. "확정" 버튼 클릭.

**처리**

- 선택한 스케줄 상태: `DRAFT` → `PUBLISHED`.
- 해당 근로자에게 Expo Push 알림 발송: "이번 주 스케줄이 확정됐습니다."
- 스케줄 확정과 동시에 해당 근로자의 근태 레코드(`EXPECTED` 상태)가 자동 생성됨 (FR-3 근태 레코드 생성 방식 참조).

**출력**: 근로자 앱에서 `PUBLISHED` 스케줄 조회 가능.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| Push 알림 발송 실패 | 최대 3회 재시도. 실패 시 관리자 화면에 "일부 알림 발송 실패" 표시 |
| 확정 후 스케줄 변경 시 | 변경 내용으로 스케줄 업데이트 + 근로자에게 "스케줄이 변경됐습니다" Push 알림 재발송 |

### FR-2.5 1:1 스케줄 교환

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 (신청·수락), 관리자 (최종 승인) |
| 플랫폼 | 앱 (근로자), 웹 (관리자) |
| 우선순위 | P2 |

#### 사용자 시나리오

근로자 A가 다음 주 화요일 근무를 근로자 B의 수요일 근무와 바꾸고 싶어 교환 요청을 보낸다. B가 수락하면 관리자가 최종 승인한다.

#### 기능 상세 설명

**신청 흐름**

1. 근로자 A: 교환할 자신의 스케줄과 상대방(B)의 스케줄 선택 후 요청 전송.
2. 근로자 B: 24시간 내 수락 또는 거절. 미응답 시 자동 취소.
   - 교환 대상 근무일까지 남은 시간이 24시간 미만이면 유효기간 자동 단축 (근무일까지 남은 시간으로 설정).
3. B가 수락 시: 관리자에게 승인 요청 알림 발송.
4. 관리자 최종 승인 시: 기존 양측 스케줄 `CANCELLED` 처리, 교환된 스케줄 신규 생성(`PUBLISHED`), 양측에 Push 알림.
5. 관리자 거절 시: 원래 스케줄 유지, 양측에 거절 알림.

**제약 조건**

- 교환은 동일 조직 내에서만 허용.
- 조직 설정에서 1:1 교환 on인 경우에만 활성화.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 요청 후 B의 스케줄이 삭제·변경된 경우 | 교환 요청 자동 취소, A에게 알림 |
| B가 24시간 내 미응답 | 교환 요청 자동 취소, A에게 "요청이 만료됐습니다" 알림 |
| 관리자가 장기 미처리인 경우 | 별도 자동 처리 없음. 관리자 판단에 위임 |

## FR-3. 근태 관리

> **근태 레코드 상태 전이**: 스케줄 `PUBLISHED` 시 `EXPECTED` 자동 생성 → 출근 체크인 시 `PRESENT` → 퇴근 체크아웃 시 `COMPLETED` → 예정 퇴근 시각 +12시간까지 미처리 시 `UNPROCESSED` (자동 전환)

### FR-3.1 GPS 기반 출퇴근 체크

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 |
| 플랫폼 | 앱 |
| 우선순위 | P1 |

#### 사용자 시나리오

근로자가 카페 출근 후 앱을 열어 출근 버튼을 누른다. 퇴근 시에는 버튼만 누르되, 오늘 30분 초과 근무를 했다면 "연장 근무" 선택 후 실제 업무 종료 시각을 입력한다.

#### 기능 상세 설명

**출근 체크 (GPS 필요)**

| 조건 | 처리 |
|---|---|
| GPS 허용 반경 내 위치 확인 | 출근 체크 허용 |
| 반경 외 위치 | 출근 차단, 오류 안내 |

- 입력: 현재 GPS 좌표 (앱 자동 수집).
- 최초 실행 시 위치 정보 수집 동의 필요.
- 다중 조직 근로자: 조직 전환 후 해당 매장 좌표 기준으로 반경 체크.
- 출력: 근태 레코드 `EXPECTED` → `PRESENT` 전환, 체크인 시각 기록.

**퇴근 체크 (GPS 불필요, 버튼 클릭만)**

| 선택 | 처리 |
|---|---|
| 일반 퇴근 | 확정 스케줄(`PUBLISHED`)의 퇴근 시각으로 기록. 버튼을 누른 시각과 무관 |
| 연장 근무 선택 | 실제 업무 종료 시각 별도 입력 (HH:MM). 입력한 시각이 퇴근 시각으로 기록 |

- 출력: 근태 레코드 `PRESENT` → `COMPLETED` 전환, 퇴근 시각 및 연장 여부 기록.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| GPS 권한 미허용 (출근 시) | "위치 권한이 필요합니다. 설정에서 허용해 주세요" 안내 |
| GPS 신호 없음 또는 정확도 부족 (출근 시) | "위치를 확인할 수 없습니다. 잠시 후 다시 시도하거나 근태 수정 요청을 이용해 주세요" 안내 |
| 반경 외 위치에서 출근 체크 시도 | "현재 위치가 매장 반경을 벗어났습니다" 안내. 체크 차단 |
| 이미 출근 체크된 상태에서 출근 재시도 | "이미 출근 처리됐습니다" 안내 |

### FR-3.2 지각·연장 하이라이팅

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 |
| 플랫폼 | 웹 |
| 우선순위 | P2 |

#### 사용자 시나리오

관리자가 근태 현황 화면을 보며 지각·연장이 발생한 근로자를 한눈에 파악하고 수당 처리 여부를 결정한다.

#### 기능 상세 설명

**지각 판정**

- 실제 체크인 시각 > 확정 스케줄 시작 시각 → 지각 하이라이팅.
- 예정 출근 시간 기준: `FIXED`는 고정 스케줄, `FLEXIBLE`은 확정 스케줄 참조.

**연장 판정**

- 근로자가 퇴근 체크 시 "연장 근무"를 선택한 경우.
- 관리자 화면에 연장 선택 여부 + 입력된 실제 종료 시각 하이라이팅.
- 별도 사전 합의 기록은 관리하지 않음. 관리자가 연장수당 포함 여부를 직접 판단.

**출력**: 근태 목록/캘린더에서 지각·연장 항목 시각적 구분 표시 (색상 또는 아이콘).

### FR-3.3 퇴근 미처리 자동화

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 (알림 수신), 관리자 (알림 수신) |
| 플랫폼 | 앱 (알림), 웹 (관리자 알림) |
| 우선순위 | P2 |

#### 사용자 시나리오

근로자가 퇴근 체크를 깜빡한 경우, 시스템이 두 차례 Push 알림을 보내고 예정 퇴근 시각 +12시간이 지나면 자동으로 "근태 미처리" 상태로 전환해 관리자 대시보드에 표시한다.

#### 기능 상세 설명

**자동화 타임라인 (cron job 기반)**

| 시점 | 처리 |
|---|---|
| 예정 퇴근 시각 +30분 | 근로자에게 1차 Push 알림: "퇴근 체크를 잊으셨나요?" |
| 예정 퇴근 시각 +2시간 | 근로자에게 2차 Push 알림: "아직 퇴근 체크가 처리되지 않았습니다." |
| 예정 퇴근 시각 +12시간 | 근태 레코드 → `UNPROCESSED` 자동 전환. 관리자 대시보드의 미처리 근태 목록에 "[근로자명] 근태 미처리"로 표시 |

- 대상: `PRESENT` 상태 (출근만 되고 퇴근 미체크) 및 `EXPECTED` 상태 (출퇴근 모두 미처리).

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 1차 알림 발송 후 퇴근 체크 완료 | 2차 알림 및 자동 전환 취소 |
| 정기 휴무일에 EXPECTED 레코드가 잘못 생성된 경우 | 발생하지 않도록 스케줄 생성 단계에서 차단 |

### FR-3.4 근태 수정 요청

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 (신청), 관리자 (승인) |

| 우선순위 | P2 |

#### 사용자 시나리오

GPS 오류로 출근 체크에 실패한 근로자가 실제 출근 시각을 입력해 수정 요청을 제출한다. 관리자가 승인하면 해당 시각으로 반영된다.

#### 기능 상세 설명

**근로자 입력값**

| 필드 | 내용 |
|---|---|
| 수정 대상 | 출근 시각 / 퇴근 시각 / 연장 종료 시각 중 선택 |

**처리 흐름**

1. 근로자 수정 요청 제출 → 관리자 화면에 검토 대기 항목 표시.

3. 관리자 거절 → 기존 근태 기록 유지. 근로자에게 거절 Push 알림.

**출력**: 승인 시 근태 레코드 업데이트 + 감사 로그 보존.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 이미 급여 계산이 완료된 근태에 수정 요청 | 수정 요청 차단. "급여 계산이 완료된 근태는 수정할 수 없습니다" 안내 |
| 동일 날짜에 중복 수정 요청 | 기존 대기 중인 요청이 있으면 새 요청 차단. 기존 요청 취소 후 재신청 가능 |

### FR-3.6 근태 확정 및 서명

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 |
| 플랫폼 | 앱 |
| 우선순위 | P1 |

#### 사용자 시나리오

정산 기간 종료 후 근로자가 자신의 근태 내역을 앱에서 확인하고 동의 버튼을 눌러 서명한다. 서명 즉시 급여 계산이 자동 실행된다.

#### 기능 상세 설명

- 근로자 앱에서 정산 대상 기간의 근태 목록(출근·퇴근 시각, 지각·연장 여부) 조회.
- "동의" 버튼 클릭 시 서명 완료.
- 저장 데이터: `signed = true`, `signed_at = 타임스탬프`.
- 서명 즉시 FR-4.2 급여 계산 자동 트리거.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 서명 후 근태 수정 요청 제출 시 | 서명 상태 초기화. 수정 요청 승인 후 재서명 필요 |
| 근태에 `UNPROCESSED` 항목이 있는 상태에서 서명 시도 | 서명 허용. 단, `UNPROCESSED` 항목은 급여 계산에서 제외됨을 안내 |

## FR-4. 급여 계산 엔진

### FR-4.1 급여 자동 계산

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 시스템 (자동) |
| 플랫폼 | 백엔드 |
| 우선순위 | P1 |

#### 사용자 시나리오

근로자 서명 완료 후 시스템이 해당 근로자의 확정 근태와 임금명세서 템플릿을 기반으로 급여를 자동 계산한다.

#### 기능 상세 설명

**입력값**

| 데이터 | 출처 |
|---|---|
| 확정 근태 레코드 (`COMPLETED` 상태) | FR-3 |
| 근로자별 임금명세서 템플릿 | FR-5.1 |
| 법정 공휴일 목록 | 시스템 내장 |

**계산 항목 (임금명세서 템플릿 기반)**

| 항목 | 계산 방식 |
|---|---|
| 기본급 | 시급 × 실근무시간 (또는 일급 × 근무일 수) |
| 주휴수당 | 주 소정근로시간 15시간 이상인 경우 지급. 소정근로시간 × 시급. 무단 결근 시 해당 주 미지급. 유급 결근은 개근으로 처리 |
| 야간수당 | 야간 시간 범위 내 실근무시간 × 시급 × (설정 비율 - 1). 기본 범위 22:00~06:00 (템플릿 단위 설정 가능) |
| 연장수당 | 연장 근무 시간 × 시급 × (설정 비율 - 1). 기준 시간 초과분에 적용 |
| 공휴일 수당 | 공휴일 근무 시간 × 시급 × (설정 비율 - 1). 템플릿에서 on인 경우만 적용 |
| 공제 | 세금·보험 설정에 따라 공제 (3.3% 원천징수 / 소득세+4대보험 / 4대보험 전체 / 고용보험만) |
| 기타 | 상여, 비과세 항목 합산 |

- 성능 목표: 1초 이하 응답.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 근로자에게 임금명세서 템플릿이 지정되지 않은 경우 | 계산 실행 차단. 관리자에게 템플릿 미지정 안내 |
| `UNPROCESSED` 상태 근태가 포함된 경우 | 해당 일자 제외하고 계산. 제외 항목 명세서에 표시 |
| 주 15시간 미만 근로자의 주휴수당 | 자동 제외 |

- 여러 근로자가 동시에 서명한 경우 병렬로 처리된다.
- 계산 완료 시 관리자 화면에 해당 근로자의 급여 계산 완료 상태 표시.

### FR-4.3 급여 명세서 발급

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 (발급), 근로자 (조회) |
| 플랫폼 | 웹 (발급), 앱 (조회) |
| 우선순위 | P1 |

#### 사용자 시나리오

급여 계산이 완료된 것을 확인한 관리자가 명세서 발급 버튼을 눌러 발급한다. 근로자는 앱에서 항목별 계산 내역을 확인한다.

#### 기능 상세 설명

**관리자: 명세서 발급**

- 급여 계산 완료 상태인 근로자에 대해 발급 버튼 활성화.
- 발급 클릭 시 명세서 상태 "발급 완료"로 변경.
- 근로자에게 Push 알림: "급여 명세서가 발급됐습니다."

**명세서 포함 내용**

| 항목 | 내용 |
|---|---|
| 기간 | 정산 대상 기간 |
| 기본급 | 시급 × 근무시간 |
| 수당 목록 | 주휴·야간·연장·공휴일 수당 각 금액 및 계산 기준 |
| 공제 목록 | 세금·보험 공제 항목 및 금액 |
| 기타 | 상여, 비과세 |
| 실수령액 | 총합 |

**근로자: 명세서 조회**

- 발급된 명세서를 앱에서 항목별로 확인 가능.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 급여 계산 미완료 상태에서 발급 시도 | 발급 버튼 비활성화 |

## FR-5. 인력 관리

---

### FR-5.1 근로자 초대·등록

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 (초대 생성·설정), 근로자 (가입·참여) |
| 플랫폼 | 웹 (관리자), 앱 (근로자) |
| 우선순위 | P1 |

#### 사용자 시나리오

관리자가 초대 링크를 생성해 카카오톡 단체방에 공유한다. 신규 아르바이트생들이 링크를 통해 소셜 로그인 후 조직에 합류한다. 이후 관리자가 각 근로자의 스케줄 타입과 시급을 설정한다.

#### 기능 상세 설명

**초대 링크**

- 링크 생성: 관리자가 조직별로 초대 링크 생성.
- 유효기간: 7일. 만료 시 관리자가 재발급.
- 다수 동시 사용 가능 (링크 1개로 여러 명 참여 가능).
- 관리자가 언제든 기존 링크를 무효화하고 새 링크 발급 가능.
- 근로자가 링크 접속 후 소셜 로그인(FR-1.2) → 조직 자동 연결.

**등록 후 관리자 설정 (필수)**

| 필드 | 내용 |
|---|---|
| 스케줄 타입 | FIXED 또는 FLEXIBLE 선택 |
| 임금명세서 템플릿 | 조직에 등록된 템플릿 중 선택 (템플릿 없으면 FR-1.4에서 먼저 생성) |

**FIXED 선택 시 추가 입력**

| 필드 | 내용 |
|---|---|
| 요일별 근무 시간 | 요일 on/off + 시작 시간 + 종료 시간 |
| 휴게 시간 | 포함 여부 체크 → 휴게 시작·종료 입력 |
| 변경 반영 시점 | 즉시 다음 근무 / 다음 주 / 다음 달 / 직접 입력 (날짜 지정) |

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 만료된 링크로 접속 | "초대 링크가 만료됐습니다. 관리자에게 새 링크를 요청해 주세요" 안내 |
| 무효화된 링크 접속 | 동일 메시지 반환 |
| 이미 해당 조직에 소속된 근로자가 링크 재사용 | "이미 이 조직의 멤버입니다" 안내. 중복 등록 차단 |
| 임금명세서 템플릿 미지정 상태로 저장 시도 | "임금명세서 템플릿을 지정해야 합니다" 안내, 저장 차단 |

### FR-5.2 퇴사 처리

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 관리자 |
| 플랫폼 | 웹 |
| 우선순위 | P2 |

#### 사용자 시나리오

계약 종료된 파트타이머를 관리자가 퇴사 처리한다. 이후 해당 근로자는 스케줄 편성에서 제외되고 앱 접근은 가능하나 해당 조직 기능은 비활성화된다.

#### 기능 상세 설명

- 소프트 딜리트. 근로자는 해당 조직에 대한 로그인 및 기능 접근 불가. (다른 조직에 소속된 경우 해당 조직은 영향 없음)
- 이후 스케줄 편성 대상에서 제외.
- 근태·급여 데이터는 근로기준법 제42조에 따라 3년 보존.
- 출력: 근로자 목록에서 "퇴직" 상태로 표시.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 미정산 급여가 있는 근로자 퇴사 처리 시도 | 경고 표시 ("미발급 급여 명세서가 있습니다"). 확인 후 진행 가능 |
| 확정된 미래 스케줄이 있는 근로자 퇴사 처리 | 해당 스케줄 `CANCELLED` 처리 후 퇴사 반영 |

### FR-5.4 근로자 다중 조직

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 근로자 |
| 플랫폼 | 앱 |
| 우선순위 | P2 |

#### 사용자 시나리오

투잡 중인 근로자가 두 매장 모두에서 초대 링크를 통해 가입한다. 앱에서 조직을 전환하며 각 매장의 스케줄·근태·급여를 별도 확인한다.

#### 기능 상세 설명

- 근로자 1명이 여러 조직에 동시 소속 가능.
- 각 조직 소속은 독립 관리: 시급·스케줄 타입(FIXED/FLEXIBLE)·임금명세서 템플릿은 조직별로 별도 지정.
- 앱 내 조직 전환 탭(또는 드롭다운)으로 컨텍스트 전환.
- 전환 후 해당 조직의 스케줄·근태·급여 데이터만 표시.
- 출근 체크 시: 현재 선택된 조직의 GPS 반경 기준으로 체크.

#### 예외 처리

| 케이스 | 처리 |
|---|---|
| 동일 시간대에 두 조직에서 스케줄이 겹치는 경우 | 시스템에서 자동 차단하지 않음. 관리자 판단에 위임 |
