## 통합 시스템 흐름

> FR별 상세 명세는 각 섹션 참조. 여기서는 여러 FR이 교차하는 핵심 루프를 엔드 투 엔드로 정리한다.

### 흐름 A — 스케줄 편성 (관리자)

1. 근무자들이 **Expo 앱**에서 관리자가 설정한 **마감 기한** 내에 **안되는 날/시간대를 입력**한다.
2. 관리자가 **시간대별 최소 인원 조건** 및 근무자별 제약 현황을 확인한다.
3. 관리자가 신청 현황을 참고해 FLEXIBLE 근무자 스케줄을 수동으로 배치하고, FIXED 근무자 스케줄은 **"스케줄 생성" 버튼**으로 일괄 생성한다.
4. 관리자가 배치 완료 후 **확정**하면 스케줄이 `PUBLISHED`로 전환되고, 근무자에게 **Expo Push 알림**이 발송된다. 이후 변경이 필요하면 관리자가 개별 수정한다.

### 흐름 B — 근무자 근태 (근무자)

1. 근무자가 Expo 앱에서 GPS 반경(기본 100m) 내 위치 확인 후 **출근 버튼을 눌러 출근 체크**한다.
2. 근무 종료 후 **일반 퇴근** 또는 **연장 근무** 버튼을 눌러 퇴근 체크한다.
   - 정상 처리되지 않았거나 관리자 확인이 필요한 근태는 관리자 화면에 **하이라이팅**으로 표시된다.
3. GPS 불가 등 오류 발생 시 **근태 수정 요청 제출** → 관리자 승인/거절 → 승인 시 반영. 관리자 직접 입력도 가능 (감사 로그 기록 + 근무자 Push 알림).

### 흐름 C — 급여 정산 (근무자·관리자)

1. 근무자가 Expo 앱에서 **근태 정보를 확인하고 서명/동의**한다 (오류 발견 시 수정 요청 제출).
2. 서명 즉시 해당 근무자의 급여 계산이 **자동으로 실행**된다. 확정 근태 기반으로 주휴·야간·연장수당이 계산되며, 여러 근무자가 동시에 서명한 경우 병렬로 처리된다.
3. 관리자가 산정 결과를 확인하고 **급여 명세서를 발급**한다.
4. 근무자가 Expo 앱에서 **명세서와 산정 기준을 확인**한다 (투명성).

## FR-1. 계정 및 조직 관리

---

### FR-1.1 관리자 계정

| 항목        | 내용            |
| ----------- | --------------- |
| 대상 사용자 | 관리자          |
| 플랫폼      | 웹 (`apps/web`) |

#### 기능 상세 설명

**가입**

| 입력값   | 유효성 조건                                                          |
| -------- | -------------------------------------------------------------------- |
| 이름     | 필수, 1자 이상                                                       |
| 이메일   | 필수, 이메일 형식, 중복 불가                                         |
| 비밀번호 | 필수, 8자 이상 128자 이하, 영문·숫자 각 1자 이상 포함, 특수문자 허용 |

- 출력: 계정 생성 완료 후 로그인 상태로 홈 이동.

**로그인**

| 입력값   | 유효성 조건 |
| -------- | ----------- |
| 이메일   | 필수        |
| 비밀번호 | 필수        |

- 출력: access token(1시간) + refresh token(7일) 발급 후 홈 이동.
- refresh token은 클라이언트에 저장. `/auth/refresh` 호출 시 새 access token 발급.

**비밀번호 재설정**

| 단계 | 입력값                     | 처리                               |
| ---- | -------------------------- | ---------------------------------- |
| 1    | 이메일                     | 가입된 이메일이면 재설정 링크 발송 |
| 2    | 새 비밀번호 (링크 접속 후) | 링크 유효기간 30분 이내            |

- 출력: 비밀번호 변경 완료 후 로그인 페이지로 이동.

**탈퇴**

- 소속 조직 및 계정 소프트 딜리트. 로그인·기능 접근 불가.
- 근태·급여 이력은 근로기준법 제42조에 따라 3년 보존.

#### 예외 처리

| 케이스                               | 처리                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------- |
| 이미 가입된 이메일로 가입 시도       | "이미 사용 중인 이메일입니다" 안내                                        |
| 로그인 실패 (이메일·비밀번호 불일치) | "이메일 또는 비밀번호가 올바르지 않습니다" 안내 (구체적인 원인 노출 금지) |
| 재설정 링크 30분 초과 접근           | "만료된 링크입니다. 재설정을 다시 요청해 주세요" 안내                     |
| 소속 조직이 있는 상태에서 탈퇴 시도  | "조직을 먼저 삭제해 주세요" 안내, 탈퇴 차단                               |

### FR-1.2 근무자 계정

| 항목        | 내용               |
| ----------- | ------------------ |
| 대상 사용자 | 근무자             |
| 플랫폼      | 앱 (`apps/mobile`) |

#### 기능 상세 설명

**소셜 로그인 (가입·로그인 통합)**

| 입력값       | 처리                                               |
| ------------ | -------------------------------------------------- |
| 카카오 OAuth | `provider=kakao`, `provider_id` 조합으로 계정 식별 |
| 네이버 OAuth | `provider=naver`, `provider_id` 조합으로 계정 식별 |

- 최초 소셜 로그인 시 계정 자동 생성.
- 재로그인 시 기존 계정 매칭.
- 출력: access token(1시간) + refresh token(7일) 발급.

**사번 입력 (최초 가입 시)**

- 소셜 로그인 직후 관리자에게 발급받은 사번 입력 화면 표시.
- 사번이 유효하면 해당 조직과 연결되고 홈 화면으로 이동.
- 이미 연결된 계정이 있으면 기존 계정과 연결 차단.

**탈퇴**

- 진행 중인 미정산 급여(서명 완료 후 명세서 미발급 상태)가 있으면 정산 완료 후 탈퇴 가능.
- 계정 소프트 딜리트. 근태·급여 이력은 익명화 후 3년 보존.

#### 예외 처리

| 케이스                                            | 처리                                                          |
| ------------------------------------------------- | ------------------------------------------------------------- |
| 소셜 플랫폼 OAuth 오류                            | "소셜 로그인에 실패했습니다. 잠시 후 다시 시도해 주세요" 안내 |
| 존재하지 않거나 이미 사용된 사번 입력             | "유효하지 않은 사번입니다. 관리자에게 확인해 주세요" 안내     |
| 소셜 로그인 완료 후 사번 미입력 상태에서 재로그인 | 사번 입력 화면으로 이동                                       |
| 미정산 급여가 있는 상태에서 탈퇴 시도             | 정산 완료 전까지 탈퇴 불가 안내                               |

#### 제약 조건

- Expo 푸시 토큰은 계정당 최신 기기 1개만 유지한다. 재설치 또는 재로그인 시 기존 토큰을 덮어쓴다.
- 다중 기기 지원은 Phase 2 범위.

## FR-2. 스케줄 관리

> **스케줄 상태**: `DRAFT` (관리자 배치 작업 중 상태, 근무자에게 비공개) → `PUBLISHED` (관리자 확정, Push 알림 발송) / `CANCELLED` (개별 취소). FIXED 스케줄은 생성 즉시 `PUBLISHED`. 확정 이후 변경이 필요하면 관리자가 개별 수정·취소·추가하며 근무자에게 변경 알림 발송.

| ------------------- | ------------------------------------------------------ |
| 스케줄 대상 기간    | 시작일, 종료일 (편성할 근무 기간)                      |
| 근무 불가 신청 기간 | 신청 시작일, 신청 마감일                               |
| 확정 마감일         | 날짜 선택 (관리자가 스케줄을 배치하고 확정하는 마감일) |

- 예외: 신청 마감일이 신청 시작일보다 이르면 저장 불가.
- 예외: 신청 마감일이 스케줄 대상 기간 시작일 이후이면 저장 불가.
- 예외: 확정 마감일이 신청 마감일보다 이르면 저장 불가.
- 예외: 확정 마감일이 스케줄 대상 기간 시작일 이후이면 저장 불가.

**출력**: 신청 내용 저장. 관리자 수동 스케줄 배치 시 참고 데이터로 활용.

### FR-2.2 스케줄 확정 및 알림

| 항목        | 내용                           |
| ----------- | ------------------------------ |
| 대상 사용자 | 관리자 (확정), 근무자 (수신)   |
| 플랫폼      | 웹 (확정), 앱 (알림 수신·조회) |

#### 기능 상세 설명

**관리자 동작**

1. 신청 마감 후 근무자별 신청 현황을 참고해 DRAFT 스케줄을 배치한다.
2. 필요 시 개별 스케줄 수동 조정 (시간 변경, 근무자 교체).
3. "확정" 버튼 클릭.

**처리**

- 선택한 스케줄 상태: `DRAFT` → `PUBLISHED`.
- 해당 근무자에게 Expo Push 알림 발송: "이번 주 스케줄이 확정됐습니다."
- 스케줄 확정과 동시에 해당 근무자의 근태 레코드(`EXPECTED` 상태)가 자동 생성됨 (FR-3 근태 레코드 생성 방식 참조).

**출력**: 근무자 앱에서 `PUBLISHED` 스케줄 조회 가능.

**PUBLISHED 스케줄 개별 수정·추가 (관리자)**

확정 이후에도 관리자는 개별 스케줄을 수정하거나 추가할 수 있다.

| 동작 | 내용                                                    |
| ---- | ------------------------------------------------------- |
| 수정 | 특정 날짜의 시작·종료 시간 변경                         |
| 취소 | 특정 날짜 스케줄 취소 (`CANCELLED` 처리)                |
| 추가 | 특정 날짜에 신규 스케줄 생성 (FIXED·FLEXIBLE 모두 가능) |

- 수정·추가 시 해당 근무자의 근태 레코드(`EXPECTED`)도 함께 업데이트.
- 취소 시 연결된 `EXPECTED` 근태 레코드도 함께 삭제.
- 수정·취소·추가 모두 근무자에게 Push 알림 발송: "스케줄이 변경됐습니다."

| 근무 시작 시각 이후 스케줄 취소 시도 | "이미 근무가 시작된 스케줄입니다. 취소할 수 없습니다" 안내, 차단  |

### FR-2.3 FIXED 스케줄 생성

| 항목        | 내용                              |

#### 기능 상세 설명

**입력값 (근무자별 설정)**

| 생성 대상 기간 내 이미 PUBLISHED 스케줄이 있을 경우 | "해당 기간에 이미 확정된 스케줄이 있습니다. 덮어쓰시겠습니까?" 확인 후 기존 PUBLISHED 스케줄 CANCELLED 처리 후 새 스케줄 생성 |
| 조직 휴무일과 근무 요일이 겹칠 경우                 | 해당 날짜 스케줄 미생성                                                                                                       |

## FR-3. 근태 관리

> **근태 레코드 상태 전이**: 스케줄 `PUBLISHED` 시 `EXPECTED` 자동 생성 → 출근 체크인 시 `PRESENT` → 퇴근 체크아웃 시 `COMPLETED`. 출퇴근 기록이 모두 없으면 `ABSENT`, 출근 기록은 있으나 퇴근 기록이 없으면 `MISSING_CHECKOUT`으로 분리 관리한다.
>
> **수정 요청 상태**: 근태 레코드 상태와 별도로 `PENDING` / `APPROVED` / `REJECTED` / `CANCELLED` 상태를 가진다.

### FR-3.1 GPS 기반 출퇴근 체크

| 항목        | 내용   |
| ----------- | ------ |
| 대상 사용자 | 근무자 |
| 플랫폼      | 앱     |

#### 기능 상세 설명

**출근 체크 (GPS 필요)**

| 조건                       | 처리                 |
| -------------------------- | -------------------- |
| GPS 허용 반경 내 위치 확인 | 출근 체크 허용       |
| 반경 외 위치               | 출근 차단, 오류 안내 |

- 입력: 현재 GPS 좌표 (앱 자동 수집).
- 최초 실행 시 위치 정보 수집 동의 필요.
- 출력: 근태 레코드 `EXPECTED` → `PRESENT` 전환, 체크인 시각 기록.

**퇴근 체크 (GPS 불필요)**

| 선택      | 처리                                                                                                  |
| --------- | ----------------------------------------------------------------------------------------------------- |
| 일반 퇴근 | 버튼을 누른 실제 시각을 퇴근 시각으로 기록                                                            |
| 연장 근무 | 버튼을 누른 실제 시각을 퇴근 시각으로 기록하고 연장 근무로 표시. 실제 연장 근무 시간과 사유 입력 가능 |

- 출력: 근태 레코드 `PRESENT` → `COMPLETED` 전환, 퇴근 시각 및 연장 근무 여부 기록.
- 퇴근 화면에는 `일반 퇴근`과 `연장 근무` 버튼을 항상 함께 표시한다.
- `연장 근무` 선택 시 `overtime_requested = true`로 저장한다.
- `연장 근무` 선택 시 앱은 확정 스케줄의 시작 시각과 종료 시각을 기본값으로 표시한다.
- 근무자는 실제 연장 근무가 발생한 출근 시각 또는 퇴근 시각을 수정해 입력할 수 있다.
- 출근 체크 시각과 퇴근 버튼 시각은 원본 기록으로 보존한다.
- 연장 근무 신청 시 입력한 시각은 `requested_overtime_start_at`, `requested_overtime_end_at` 성격의 요청값으로 관리한다.
- `연장 근무` 선택 시 `overtime_reason`을 선택 입력할 수 있다.
- 관리자가 확인한 연장 근무 시간만 급여 계산에 반영한다.
- 스케줄 종료 시각 +12시간까지 출근·퇴근 기록이 모두 없으면 근태 레코드를 `ABSENT`로 전환하고 관리자 화면에 하이라이팅한다.
- 스케줄 종료 시각 +12시간까지 출근 기록은 있으나 퇴근 기록이 없으면 근태 레코드를 `MISSING_CHECKOUT`으로 전환하고 관리자 화면에 하이라이팅한다.

#### 예외 처리

| 케이스                                   | 처리                                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| GPS 권한 미허용 (출근 시)                | "위치 권한이 필요합니다. 설정에서 허용해 주세요" 안내                                    |
| GPS 신호 없음 또는 정확도 부족 (출근 시) | "위치를 확인할 수 없습니다. 잠시 후 다시 시도하거나 근태 수정 요청을 이용해 주세요" 안내 |
| 반경 외 위치에서 출근 체크 시도          | "현재 위치가 매장 반경을 벗어났습니다" 안내. 체크 차단                                   |
| 이미 출근 체크된 상태에서 출근 재시도    | "이미 출근 처리됐습니다" 안내                                                            |
| 출근 체크 없이 퇴근 시도                 | "출근 기록이 없어 퇴근 처리할 수 없습니다. 근태 수정 요청을 이용해 주세요" 안내          |
| 이미 퇴근 체크된 상태에서 퇴근 재시도    | "이미 퇴근 처리됐습니다" 안내                                                            |

### FR-3.2 근태 예외 하이라이팅

| 항목        | 내용   |
| ----------- | ------ |
| 대상 사용자 | 관리자 |
| 플랫폼      | 웹     |

#### 기능 상세 설명

관리자 화면에서는 정상 처리되지 않았거나 관리자 확인이 필요한 근태를 하이라이팅한다.

**지각 판정**

- 실제 체크인 시각 > 확정 스케줄 시작 시각이면 `is_late = true`로 저장하고 지각 하이라이팅.
- 지각 시간은 실제 체크인 시각 - 확정 스케줄 시작 시각으로 계산한다.
- 근태 상태는 지각 여부와 관계없이 출근·퇴근 기록이 모두 있으면 `COMPLETED`가 된다.
- 예정 출근 시간 기준: `FIXED`는 고정 스케줄, `FLEXIBLE`은 확정 스케줄 참조.

**연장 판정**

- 근무자가 퇴근 체크 시 "연장 근무"를 선택해 `overtime_requested = true`로 저장된 경우.
- 관리자 화면에 원본 출근·퇴근 시각, 요청 연장 시작·종료 시각, 사유(입력한 경우)를 표시한다.
- 별도 사전 합의 기록은 관리하지 않음. 관리자가 연장수당 포함 여부를 직접 판단.

**결근·퇴근 누락 판정**

- 스케줄 종료 시각 +12시간까지 출근·퇴근 기록이 모두 없으면 `ABSENT`로 하이라이팅.
- 스케줄 종료 시각 +12시간까지 출근 기록은 있으나 퇴근 기록이 없으면 `MISSING_CHECKOUT`으로 하이라이팅.

**수정 요청 판정**

- 수정 요청 상태가 `PENDING`이면 수정 요청 대기 항목으로 하이라이팅.
- 수정 요청 사유 유형은 상세 화면에서 표시한다.

**출력**: 근태 목록/캘린더에서 지각, 연장, 결근, 퇴근 누락, 수정 요청 대기 항목을 하이라이팅한다.

### FR-3.3 근태 수정 요청

| 항목        | 내용                         |
| ----------- | ---------------------------- |
| 대상 사용자 | 근무자 (신청), 관리자 (승인) |
| 플랫폼      | 앱 (신청), 웹 (승인)         |

#### 기능 상세 설명

**근무자 입력값**

| 필드                | 내용                                                                             |
| ------------------- | -------------------------------------------------------------------------------- |
| 요청 사유 유형      | GPS 오류 / 출근 누락 / 퇴근 누락 / 결근 처리 이의제기 / 연장 정정 / 기타 중 선택 |
| 요청 출근 시각      | 필요한 경우 입력 (HH:MM)                                                         |
| 요청 퇴근 시각      | 필요한 경우 입력 (HH:MM)                                                         |
| 사유                | 요청 사유 유형이 `기타`인 경우 필수 입력. 그 외 유형은 선택 입력                 |

- 연장 근무 여부는 퇴근 체크 시 `일반 퇴근` / `연장 근무` 선택으로 기록한다.
- 요청 사유 유형이 `연장 정정`인 경우, 입력된 요청 출근 시각·요청 퇴근 시각을 기준으로 관리자가 연장 근무 반영 여부를 결정한다.

**처리 흐름**

1. 근무자 수정 요청 제출 → 수정 요청 상태 `PENDING`, 관리자 화면에 검토 대기 항목 표시.
2. 관리자 승인 → 요청 출근 시각, 요청 퇴근 시각 중 입력된 항목을 근태 레코드에 반영. 연장 정정 요청인 경우 관리자가 인정한 연장 근무 시간만 급여 계산에 반영. 감사 로그에 "근무자 수정 요청 승인" 기록.
3. 관리자 거절 → 기존 근태 기록 유지. 근무자에게 거절 Push 알림.

**출력**: 승인 시 근태 레코드 업데이트 + 감사 로그 보존.

#### 예외 처리

| 동일 날짜에 중복 수정 요청    | 기존 대기 중인 요청이 있으면 새 요청 차단. 기존 요청 취소 후 재신청 가능                                     |

- 감사 로그에 "관리자 직접 입력" + 입력한 관리자 계정 ID + 타임스탬프 기록.

| 연장수당 | 관리자가 인정한 연장 근무 시간 × 기준 임금 × (연장수당 배율 - 1)                                                                    |
| 공제     | 세금 유형에 따라 계산                                                                                                               |
| 기타     | 추가 지급/공제 항목 합산                                                                                                            |

### FR-4.3 급여 명세서 발급

| 항목        | 내용                         |
| ----------- | ---------------------------- |
| 대상 사용자 | 관리자 (발급), 근무자 (조회) |
| 플랫폼      | 웹 (발급), 앱 (조회)         |

#### 기능 상세 설명

**관리자: 추가 지급·공제 항목 입력**

`calculated` 상태에서 발급 전, 관리자가 자유롭게 추가 항목을 입력할 수 있다.

| 필드   | 내용                                       |
| ------ | ------------------------------------------ |
| 항목명 | 텍스트 입력 (예: 명절 보너스, 식대 공제)   |
| 유형   | 추가 지급(PAYMENT) / 공제(DEDUCTION) 선택  |
| 금액   | 양수 금액 입력. 부호는 유형으로 구분       |

- 복수 추가 가능. 항목 추가·삭제 시 `net_pay` 즉시 재계산.
- 발급 완료(`issued`) 후에는 추가·수정·삭제 불가.

**관리자: 명세서 발급**

- 급여 명세서 상태가 `calculated`인 근무자에 대해 발급 버튼 활성화.
- 발급 클릭 시 급여 명세서 상태를 `issued`로 변경.
- 근무자에게 Push 알림: "급여 명세서가 발급됐습니다."

**명세서 상태**

| 상태         | 의미                                  |
| ------------ | ------------------------------------- |
| `calculating` | 근무자 서명 후 계산 진행 중           |
| `calculated`  | 급여 계산 완료. 관리자 발급 대기 상태 |
| `issued`      | 관리자 발급 완료. 근무자 조회 가능    |

**명세서 포함 내용**

| 항목             | 내용                                              |
| ---------------- | ------------------------------------------------- |
| 정산 기간        | `period_start` ~ `period_end`                     |
| 지급일           | `pay_date`                                        |
| 급여 타입        | 시급 / 일급 / 월급                                |
| 기준 금액        | 시급 / 일급 / 월급 중 적용된 금액                 |
| 근무 시간/일수   | 정산 기간 내 확정 근태 기준                       |
| 기본급           | 급여 타입에 따라 계산된 금액                      |
| 수당             | 주휴수당, 야간수당, 연장수당 각 금액 및 계산 기준 |
| 공제             | 세금 유형에 따른 공제 항목 및 금액                |
| 추가 지급/공제   | 기타 지급·공제 항목                               |
| 실수령액         | 기본급 + 수당 + 추가 지급 - 공제                  |
| 계산 기준 스냅샷 | 계산 시점의 임금명세서 템플릿 값                  |

**근무자: 명세서 조회**

- `issued` 상태의 명세서를 앱에서 항목별로 확인 가능.

#### 예외 처리

| 케이스                                         | 처리                                   |
| ---------------------------------------------- | -------------------------------------- |
| 급여 계산 미완료 상태에서 발급 시도            | 발급 버튼 비활성화                     |
| 발급 완료 후 추가 지급·공제 항목 수정 시도     | 입력 UI 비활성화. 수정 불가 안내       |

| 이름             | 템플릿 이름 (`pay_policies.name`)                                        |
| 급여 타입        | 시급 / 일급 / 월급 중 선택                                               |
| 타입별 금액      | 선택한 급여 타입에 따라 시급 / 일급 / 월급 중 하나의 금액 입력           |
| 세금 유형        | 3.3% / 4대보험 / 4대보험+소득세 / 고용보험만                             |
| 야간수당 배율    | 야간수당 계산에 적용                                                     |
| 연장수당 배율    | 연장수당 계산에 적용                                                     |
| 정산 기간·지급일 | 모든 급여 타입에서 입력. `period_start_day`, `period_end_day`, `pay_day` |

**처리**

- 급여 타입이 시급이면 시급만 저장하고 일급·월급은 저장하지 않는다.
- 급여 타입이 일급이면 일급만 저장하고 시급·월급은 저장하지 않는다.
- 급여 타입이 월급이면 월급만 저장하고 시급·일급은 저장하지 않는다.
- 정산 기간과 지급일은 모든 급여 타입에서 필수 입력한다.
- 이미 근무자에게 지정된 템플릿은 삭제 시 소프트 딜리트 처리한다.
- 템플릿 수정 후에도 기존 급여 계산 이력은 계산 당시 저장된 스냅샷을 기준으로 유지한다.
