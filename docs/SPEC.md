# 기능 명세서 — 프래그먼트

이 문서는 PRD의 MVP 범위를 개발 실행 가능한 수준으로 정리합니다. MVP는 단일 조직의 인력 정보, 가능 시간, 최소 인원 조건을 기반으로 스케줄 초안을 추천하고, 사용자가 조정·확정·보관하는 흐름만 포함합니다.

## 1. 공통 원칙

### 1.1 조직 범위

- 계정 1개는 MVP에서 조직 1개만 사용합니다.
- 조직이 없는 계정은 대시보드와 운영 기능에 진입할 수 없고 `/organization/new`로 이동합니다.

### 1.2 웹 대응

- 운영 웹은 데스크톱과 모바일 브라우저에서 모두 사용할 수 있어야 합니다.
- 데스크톱과 모바일 브라우저에서 동일한 핵심 기능을 제공해야 합니다.

### 1.3 스케줄 도메인 상태

| 상태 | 의미 |
| --- | --- |
| `DRAFT` | 추천 생성 후 사용자가 조정 중인 스케줄 |
| `CONFIRMED` | 확정된 최종 스케줄 |

선택 기간에 생성된 스케줄이 없으면 UI에서는 `스케줄 없음`으로 표시합니다. 이 값은 DB에 저장되는 스케줄 상태가 아닙니다.

## 2. 전체 흐름

```txt
회원가입 또는 로그인
→ 조직이 없으면 단일 조직 생성
→ 인력 등록
→ 근무 기간 선택 및 인력별 가능 시간 입력
→ 최소 인원 조건 입력
→ 스케줄 추천 생성
→ DRAFT 스케줄 조정
→ 스케줄 확정
→ 대시보드 또는 보관함에서 확정 스케줄 조회/export
```

## 3. 기능 명세

### FR-1. 회원가입

| 항목 | 내용 |
| --- | --- |
| 경로 | `/signup` |
| 목적 | 새 계정을 생성하고 로그인 상태로 전환 |

#### 입력값

| 필드 | 조건 |
| --- | --- |
| 이름 | 필수 |
| 이메일 | 필수, 이메일 형식, 중복 불가 |
| 비밀번호 | 필수 |
| 비밀번호 확인 | 필수, 비밀번호와 일치 |

#### 동작

1. 사용자가 이름, 이메일, 비밀번호, 비밀번호 확인을 입력합니다.
2. 회원가입 요청 시 입력값을 검증합니다.
3. 계정 생성 성공 시 자동 로그인 처리합니다.
4. 조직이 아직 없으므로 `/organization/new`로 이동합니다.

#### 예외

| 케이스 | 처리 |
| --- | --- |
| 이메일 형식 오류 | 입력 검증 메시지 표시 |
| 비밀번호 확인 불일치 | 입력 검증 메시지 표시 |
| 이미 가입된 이메일 | 이미 사용 중인 이메일 안내 메시지 표시, 가입 중단 |

### FR-2. 로그인

| 항목 | 내용 |
| --- | --- |
| 경로 | `/login` |
| 목적 | 기존 계정으로 서비스 진입 |

#### 입력값

| 필드 | 조건 |
| --- | --- |
| 이메일 | 필수 |
| 비밀번호 | 필수 |

#### 동작

1. 사용자가 이메일과 비밀번호를 입력합니다.
2. 로그인 성공 후 조직 존재 여부를 확인합니다.
3. 조직이 없으면 `/organization/new`로 이동합니다.
4. 조직이 있으면 `/dashboard`로 이동합니다.

#### 예외

| 케이스 | 처리 |
| --- | --- |
| 필수값 누락 | 입력 검증 메시지 표시 |
| 인증 실패 | 이메일 또는 비밀번호 오류 메시지 표시 |

### FR-3. 조직 생성 및 수정

| 항목 | 내용 |
| --- | --- |
| 생성 경로 | `/organization/new` |
| 수정 경로 | `/organization` |
| 목적 | 스케줄 추천 기준이 되는 조직 운영 정보를 관리 |

#### 입력값

| 필드 | 조건 |
| --- | --- |
| 조직명 | 필수 |
| 매주 휴무일 | 선택, 요일 복수 선택 |
| 요일별 운영 시작 시간 | 휴무일이 아닌 요일은 필수 |
| 요일별 운영 종료 시간 | 휴무일이 아닌 요일은 필수, 시작 시간과 같을 수 없음 |

#### 동작

1. 조직 생성 시 매주 휴무일을 먼저 선택합니다.
2. 휴무일로 선택된 요일의 운영 시간 입력은 비활성화합니다.
3. 휴무일이 아닌 요일은 운영 시작 시간과 종료 시간을 입력합니다.
4. 종료 시간이 시작 시간보다 빠르면 다음 날 종료되는 운영 시간으로 저장합니다.
5. 조직 생성 성공 시 `/dashboard`로 이동합니다.
6. 조직 수정 시 기존 값을 불러와 같은 규칙으로 수정합니다.

#### 예외

| 케이스 | 처리 |
| --- | --- |
| 조직명 누락 | 저장 차단 |
| 운영 시간 누락 | 해당 요일 저장 차단 |
| 종료 시간이 시작 시간과 같음 | 저장 차단 |
| 종료 시간이 시작 시간보다 빠름 | 익일 종료로 처리 |

### FR-4. 인력 관리

| 항목 | 내용 |
| --- | --- |
| 경로 | `/workers` |
| 목적 | 스케줄 추천에 사용할 인력 기본 정보 관리 |

#### 조회 데이터

| 항목 | 내용 |
| --- | --- |
| 이름 | 인력 이름 |
| 사번 | 시스템 자동 생성 번호 |
| 주간 계약 시간 | 주 단위 계약 시간 |

#### 생성 입력값

| 필드 | 조건 |
| --- | --- |
| 이름 | 필수 |
| 주간 계약 시간 | 필수, 1 이상의 숫자 |

사번은 생성 시 서버가 자동 발급하며 사용자가 직접 입력하지 않습니다.

#### 수정 입력값

| 필드 | 조건 |
| --- | --- |
| 이름 | 필수 |
| 사번 | 읽기 전용 |
| 주간 계약 시간 | 필수, 1 이상의 숫자 |

#### 동작

1. 사용자는 인력을 생성할 수 있습니다.
2. 저장 성공 시 인력 목록에 추가됩니다.
3. 사용자는 기존 인력의 이름과 주간 계약 시간을 수정할 수 있습니다.
4. 사용자는 더 이상 사용하지 않는 인력을 삭제할 수 있습니다.
5. 삭제된 인력은 이후 추천 생성 기준에서 제외됩니다.

### FR-5. 가능 시간 관리

| 항목 | 내용 |
| --- | --- |
| 경로 | `/availability` |
| 목적 | 인력별로 스케줄 배정 가능한 날짜와 시간 입력 |

#### 가능 시간 생성 규칙

| 항목 | 규칙 |
| --- | --- |
| 날짜 범위 | 근무 시작 날짜부터 근무 종료 날짜까지 |
| 시간 범위 | 조직의 요일별 운영 시간 기준 |
| 시간 단위 | 30분 |
| 휴무일 | 가능 시간 입력 불가 |

운영 종료 시간이 익일인 경우에도 같은 영업일 기준으로 처리하며, 저장 시에는 실제 날짜가 반영된 시작/종료 datetime으로 저장합니다.

#### 입력 및 저장

1. 사용자가 근무 시작 날짜와 종료 날짜를 선택합니다.
2. 인력을 선택하면 해당 인력의 기존 가능 시간을 불러옵니다.
3. 사용자는 30분 단위로 가능 시간을 선택하거나 선택 해제합니다.
4. 선택된 시간이 연속되면 하나의 구간으로 관리합니다.
   - 예: `10:00~10:30`, `10:30~11:00`, `11:00~11:30` → `10:00~11:30`
5. 저장 시 선택된 전체 가능 시간을 반영합니다.

#### 수정 및 삭제

- 기존 가능 시간은 조회 후 수정할 수 있습니다.
- 수정은 가능 시간 구간을 추가하거나 제거한 뒤 저장합니다.
- 삭제는 기존 가능 시간 구간을 제거한 뒤 저장합니다.

#### 검증

| 케이스 | 처리 |
| --- | --- |
| 시작 날짜 없음 | 저장 차단 |
| 종료 날짜 없음 | 저장 차단 |
| 종료 날짜가 시작 날짜보다 빠름 | 저장 차단 |
| 인력 미선택 | 저장 차단 |
| 휴무일에 해당하는 시간 선택 | 저장 차단 |

### FR-6. 최소 인원 조건

| 항목 | 내용 |
| --- | --- |
| 경로 | `/staffing-rules` |
| 목적 | 스케줄 추천 시 요일과 시간대별 필요한 인원 수 정의 |

#### 조회 데이터

| 항목 | 내용 |
| --- | --- |
| 요일 | 조건이 적용되는 요일 |
| 시작 시간 | 조건 시작 시간 |
| 종료 시간 | 조건 종료 시간 |
| 필요 인원 | 해당 시간대에 필요한 최소 인원 수 |

#### 입력값

| 필드 | 조건 |
| --- | --- |
| 요일 | 필수 |
| 시작 시간 | 필수 |
| 종료 시간 | 필수, 시작 시간과 같을 수 없음 |
| 필요 인원 | 필수, 1 이상의 정수 |

#### 동작

1. 사용자는 최소 인원 조건을 생성할 수 있습니다.
2. 저장 성공 시 조건 목록에 추가됩니다.
3. 사용자는 기존 조건을 수정할 수 있습니다.
4. 사용자는 기존 조건을 삭제할 수 있습니다.
5. 종료 시간이 시작 시간보다 빠르면 다음 날 종료되는 조건으로 저장합니다.

### FR-7. 스케줄

| 항목 | 내용 |
| --- | --- |
| 경로 | `/schedules` |
| 목적 | 추천 생성, DRAFT 조정, 확정 |

#### 추천 생성 조건

- 조직이 있어야 합니다.
- 인력이 1명 이상 있어야 합니다.
- 선택 기간에 저장된 가능 시간이 1개 이상 있어야 합니다.
- 최소 인원 조건이 1개 이상 있어야 합니다.
- 같은 입력 조건으로 이미 생성된 DRAFT가 있으면 중복 생성하지 않습니다.

#### 추천 생성 동작

1. 사용자가 추천 생성을 요청합니다.
2. 서버는 인력, 가능 시간, 최소 인원 조건, 선택 기간을 기준으로 DRAFT 스케줄을 생성합니다.
3. 생성된 스케줄은 `DRAFT` 상태로 저장합니다.
4. 최소 인원 조건을 충족하지 못한 날짜와 시간대가 있으면 미충족 조건으로 기록합니다.

#### 스케줄 추가/수정 입력값

| 필드 | 조건 |
| --- | --- |
| 날짜 | 필수 |
| 시작 시간 | 필수 |
| 종료 시간 | 필수, 시작 시간과 같을 수 없음 |
| 인력 | 필수 |

종료 시간이 시작 시간보다 빠르면 다음 날 종료되는 스케줄로 저장합니다.

#### 확정

1. DRAFT 스케줄이 1개 이상 있으면 확정할 수 있습니다.
2. 확정 시 상태를 `CONFIRMED`로 변경합니다.
3. 확정 후에는 대시보드와 보관함에서 조회할 수 있습니다.

### FR-8. 보관함

| 항목 | 내용 |
| --- | --- |
| 경로 | `/schedule-history` |
| 목적 | 확정 스케줄 이력 조회 및 CSV export |

#### 필터

| 필드 | 조건 |
| --- | --- |
| 연도 | 필수 |
| 월 | 선택 |

월을 선택하지 않으면 해당 연도의 확정 이력을 조회합니다. 월을 선택하면 해당 연도와 월에 포함되는 확정 이력만 조회합니다.

#### 동작

1. 사용자가 연도 또는 월을 선택합니다.
2. 조건에 맞는 확정 이력 목록을 조회합니다.
3. 이력을 선택하면 확정 스케줄을 조회합니다.
4. 선택한 이력을 CSV로 내보냅니다.

보관함은 `CONFIRMED` 스케줄의 조회와 CSV export를 제공합니다.

### FR-9. 대시보드

| 항목 | 내용 |
| --- | --- |
| 경로 | `/dashboard` |
| 목적 | 조직 정보와 최근 확정 스케줄 확인 |

#### 조회 데이터

| 항목 | 내용 |
| --- | --- |
| 조직명 | 현재 조직 이름 |
| 매주 휴무일 | 조직의 휴무 요일 |
| 요일별 운영 시간 | 조직의 운영 시작/종료 시간 |
| 확정 스케줄 | 가장 최근 확정 스케줄 |

#### 동작

1. 조직 정보를 조회합니다.
2. 가장 최근 확정 스케줄을 조회합니다.
3. 확정 스케줄의 기간과 CSV export 액션을 제공합니다.
4. 조직 수정 요청 시 `/organization`으로 이동합니다.

대시보드의 확정 스케줄은 조회와 CSV export만 제공합니다.

## 4. API 계약 작성 기준

상세 엔드포인트는 별도 API 명세에서 확정합니다. 이 문서에서는 기능과 도메인 동작 기준만 정의합니다.

API 명세 작성 시 최소한 아래 항목을 포함합니다.

- 요청 메서드와 경로
- 요청 파라미터와 body
- 응답 데이터
- 실패 응답
- 인증 필요 여부
- 조직 단위 데이터 접근 조건
